## 当前 v0.39 基线

局部固定长度数组已支持显式 `int[]`、`string[]`、`bool[]` 和有类型空数组，元素同构、初始化从左到右单次求值。只读零基 int 索引具备静态和动态越界检查；元素读取可复用标量表达式、实参和返回，但数组本身不能逃逸或整体复制。

完整 449 项测试通过，数组 C 示例输出 `95`、`LAI`、`1`；现有 C/LLVM 示例通过，LLVM 对数组仍明确报能力错误。

## 历史 v0.38 基线

v0.38 已在共享 checker 中实现路径级控制流分析：支持 guard clause 和分支/循环中的通用函数早退，要求返回值函数所有可达路径返回，并在第一条不可达语句处报错。分析结果包括 `fallthrough`、`return`、`break`、`continue`、`diverge`，其中发散不能代替返回。

静态无限循环证明只识别字面量 `true` 及其嵌套括号；普通 `while` 和 `for` 仍保守处理。没有实现裸/void/main return、通用常量折叠、静态非空 `for` 证明或 LLVM 控制流。

`examples/general_early_return.ly` 的 C 输出为 `-1`、`0`、`1`、`7`、`8`；LLVM 在第 1 行因 `FunctionDef` 不支持而拒绝。v0.38 发布基线为 399 项单元测试通过。

v0.37 的单一 checked i32、动态 C runtime helper、`for` 三值单次求值、动态正 step 检查、i32 上界安全推进和 collision-free 内部前缀仍是当前能力。

## 已确认的数组任务拆分

- 数组创建后长度固定，不支持 `append`、`remove` 或自动扩容。
- v0.39 数组必须显式声明类型，例如 `let scores: int[] = [90, 95, 100]` 和 `let empty: int[] = []`。
- v0.39 首批支持 `int[]`、`string[]`、`bool[]`，字面量元素必须与声明类型一致。
- 固定长度不等于元素不可变：元素允许修改，但索引更新排入 v0.40，v0.39 只做创建和读取。
- v0.39 已实现 `scores[index]`，严格零基 int 索引，负索引非法；局部 C 存储，静态越界编译失败，动态越界访问前失败退出。
- v0.40 再确认只读长度 API 和最小遍历语法；元素更新不能改变数组长度。
- v0.41 推进多维数组；`int[][]`、矩形/交错语义和内存模型留到该版本独立设计，不提前算作 v0.39 能力。
- 动态长度容器与数组分离，未来按 `list<T>` 独立设计扩容、`append`、`remove`、索引和遍历；当前进入待编号开发池。

## 尚未编号

- 数组参数与返回：先确定生命周期、所有权和跨函数传递规则。
- 整数组复制与整体赋值：先确定值复制/别名、长度兼容和存储语义，不默认归入 v0.40 或 v0.41。
- 动态列表、字典、函数易用性、通用类型标注与完整类型推导等，已登记到全局路线图的待编号池。
- 模块/包管理、并发、GC/JIT 等仍属长期愿景，没有确定交付版本。LLVM v0.45 只复盘拆分后续路线，不承诺一版追平默认 C 后端。

## 路线图使用规则

- 版本号表示小范围阶段目标，不能把 v0.40-v0.45 的规划写成 v0.39 已实现能力。
- 每次只推进一个可运行、可测试的闭环；先写设计/计划，再修改语言实现。
- 新增用户可见语法时，先向用户给出 2-3 个有意义候选、示例、利弊、与 LAI 一致性和明确推荐。
- 数组扩展、字符串用户库、浮点和 LLVM SSA 仍是未来工作，局部数组核心则已经实现。
