# LAI 架构与编译流程

历史同步：2026-07-29。本地更新：2026-09-07。当前 v0.40 第一阶段默认实现是完整 checked C 后端；LLVM 为受限实验性旁路。本次未访问或上传有道云。

```text
main.ly -> lexer -> parser -> AST -> semantic/type/flow checker -> backend -> clang -> exe
```

默认后端细化为：

```text
main.ly -> lexer -> parser -> AST -> semantic/type/flow checker -> C codegen + stdlib helpers -> clang -> build/main.exe
```

## 阶段与职责

1. `lai_compiler.py` 的 lexer 将源码转为 token，parser 将 token 组装为 AST；同文件还拥有 `compile_source`、`compile_file` 与 CLI。
2. `lai_ast.py` 定义不可变 AST 节点，使 parser、checker 和两个后端共享同一种程序表示。
3. `lai_checker.py` 对 AST 做语义、类型和路径级控制流检查；失败时通过 `lai_core.py` 的 `LaiCompileError` 给出带行号的错误。
4. `lai_backend.py` 的 `Backend` 描述符为编译入口提供后端边界；默认值是 C 后端。
5. `lai_c_backend.py` 将完整已检查 AST 生成为 C；`lai_stdlib.py` 提供 C preamble、字符串转义、`print` 和私有 checked i32 runtime。
6. `lai_llvm_backend.py` 只接受明确的整数 `print` 子集，生成文本 LLVM IR；用户函数和控制流以能力错误拒绝。
7. `lai_clang.py` 集中调用 `clang` 并保留既有错误措辞，最终生成 `.exe`。

## v0.39 局部数组链路

1. parser 将 `let scores: int[] = [90, 95]` 解析为带 `type_name` 的 `LetStmt` 和 `ArrayExpr`；`scores[i]` 成为 `IndexExpr`。
2. checker 的 `_check_array_declaration` 逐元素确认类型后记录 `ArrayType("int", 2)`。自身初始化引用不提前可见。
3. `_infer_index_type` 确认目标是局部数组、索引是 int，复用静态 i32 求值拒绝负索引或上界越界；返回元素标量类型。
4. C 后端的 `_array_declaration_to_c` 为每个数组选择内部存储名，再逐条写入初始值，保证左到右单次求值。
5. `_index_to_c_value` 为动态索引调用 `c_array_runtime_support` 生成的 helper，检查 `0 <= index < length` 后才读取，保留逻辑短路。

空数组物理占位 1、逻辑长度 0；不生成零长 C 数组、VLA 或堆分配。数组存储随块生命周期结束，本版不能传参、返回、整体复制或赋值。内部名称避开用户名称，避免遮蔽同名函数。

完整回归 449 项通过，数组示例输出 `95`、`LAI`、`1`；生成 C 在 `clang -std=c11 -pedantic-errors -O2` 下也构建运行成功。动态错误带行号、索引、长度并失败退出。实验性 LLVM 不扩展数组能力。

## v0.40 第一阶段元素修改链路

parser 生成不可变 `IndexAssignStmt(target: IndexExpr, operator, value, line)`；checker 的 `_check_index_assignment` 复用 `_infer_index_type`，三种元素允许同型 `=`，仅 `int` 元素支持五种复合赋值，保留静态零除、类型和边界检查，正常 fallthrough，不改变数组长度。

C 后端 `_index_assignment_to_c` 先保存已检查的元素地址，再读取旧值（复合赋值），再求值右值，全部成功才写入；各阶段是单次执行的独立 C 完整表达式，复合运算沿用 checked i32 helper。索引失败不执行右值，右值或算术失败不写入。字符串 slot 为 `const char**`，只替换指针，不修改字符串字节，也不开放用户指针或跨函数数组。

最终完整 `-q` / `-v` 回归均为 480 项通过、无 skip；新示例默认 C 与严格 C11 / `-O2` 输出 `85`、`60`、`10`、`after`、`1`，LLVM 按预期拒绝。详细证据见 `docs/ai/active-context.md`。

## v0.38 控制流分析

共享 checker 为语句和语句块计算一组可能结果：`fallthrough`、`return`、`break`、`continue`、`diverge`。

- 顺序语句只沿 `fallthrough` 继续；如果进入下一条语句前已经没有 `fallthrough`，就在该语句行报告第一条不可达语句。
- `if` 合并 then/else 的结果；缺少 `else` 会贡献 `fallthrough`，因此 guard clause 后的外层语句仍可覆盖剩余路径。
- 普通 `while` 和 `for` 保留循环可能零次执行的 `fallthrough`，同时传播 body 的 `return` 与 `diverge`；`break`、`continue` 由当前循环消费。
- 仅 `true`、`(true)` 及更深的括号形式被视为静态 true。这样的 `while` 若无可达 `break`，可由 body 证明全路径返回；继续运行或内层无限循环产生的 `diverge` 仍不能满足返回值函数。
- 返回值函数最终结果必须只有 `return`，从而保证所有可达路径返回。

v0.38 没有新增语法或 C lowering。`examples/general_early_return.ly` 在 C 路径输出 `-1`、`0`、`1`、`7`、`8`；LLVM 在第 1 行因 `FunctionDef` 不支持而拒绝。发布基线是 399 项单元测试通过。

## v0.37 整数安全链路继续有效

`int` 只有一种 checked i32 语义，没有性能或 unchecked 模式。纯静态表达式由共享 checker 按中间结果诊断零除与溢出；动态 C 表达式调用私有 runtime helper。`for` 在进入循环前按源码顺序保存 start/end/step，动态 step 为非正时立即失败，`for_advance` 以更宽中间值判断是否越界终止。每次生成收集用户名称并选择 collision-free 内部前缀。

逻辑 AST 仍由 C 的 `!`、`&&`、`||` 保持短路，因此未执行逻辑 operand 中的 runtime helper 不会运行。实验性 LLVM 仅支持经共享 checker 检查的顶层纯整数 `print`，动态值、用户函数与控制流仍报能力错误。

## 关键模块关系

| 模块 | 边界 |
| --- | --- |
| `lai_compiler.py` | 编译入口和语法前端，不承载全部后端细节。 |
| `lai_ast.py` | 新增语法节点的唯一优先落点。 |
| `lai_checker.py` | 源码语义、类型、返回路径和不可达规则的权威执行点。 |
| `lai_backend.py` | 后端通用协议，保持 C/LLVM 选择可注入。 |
| `lai_c_backend.py` | 全量默认后端，负责 C 生成和构建。 |
| `lai_llvm_backend.py` | 受限 IR emitter，不用 `llvmlite`，不代表完整 LLVM 支持。 |
| `lai_clang.py` | 公共编译器进程调用层。 |
| `lai_stdlib.py` | 仅内部 C 输出运行时辅助，不增加 LAI 用户 API。 |
| `lai_int.py` | i32 常量边界和静态整数字面量树求值。 |
| `lai_types.py` | 数组元素类型、局部长度及只接受局部名称的索引目标辅助。 |

v0.40 第一阶段元素修改已实现，只读长度 API 和遍历仍在 v0.40 待实现，不代表全量完成；多维数组仍在 v0.41，v0.40-v0.45 共 6 个编号版本尚有工作。数组跨函数流转、整体复制、通用常量折叠、静态非空 `for` 证明和 LLVM 控制流仍未实现。
