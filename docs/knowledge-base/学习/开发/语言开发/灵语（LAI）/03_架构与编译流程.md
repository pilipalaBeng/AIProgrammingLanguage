# LAI 架构与编译流程

最后同步：2026-07-28。默认实现是完整 C 后端；LLVM 为受限实验性旁路。

```text
main.ly -> lexer -> parser -> AST -> semantic/type checker -> backend -> clang -> exe
```

默认后端细化为：

```text
main.ly -> lexer -> parser -> AST -> semantic/type checker -> C codegen + stdlib helpers -> clang -> build/main.exe
```

## 阶段与职责

1. `lai_compiler.py` 的 lexer 将源码转为 token，parser 将 token 组装为 AST；同文件还拥有 `compile_source`、`compile_file` 与 CLI。
2. `lai_ast.py` 定义不可变 AST 节点，使 parser、checker 和两个后端共享同一种程序表示。
3. `lai_checker.py` 对 AST 做语义和基础类型检查；失败时通过 `lai_core.py` 的 `LaiCompileError` 给出带行号的错误。
4. `lai_backend.py` 的 `Backend` 描述符为编译入口提供后端边界；默认值是 C 后端。
5. `lai_c_backend.py` 将完整已检查 AST 生成为 C；`lai_stdlib.py` 提供 C preamble、字符串转义和 `print` 的输出片段。
6. `lai_llvm_backend.py` 只接受明确的整数 `print` 子集，生成文本 LLVM IR；其他合法 LAI AST 以能力错误拒绝。
7. `lai_clang.py` 集中调用 `clang` 并保留既有错误措辞，最终生成 `.exe`。

## 关键模块关系

| 模块 | 边界 |
| --- | --- |
| `lai_compiler.py` | 编译入口和语法前端，不承载全部后端细节。 |
| `lai_ast.py` | 新增语法节点的唯一优先落点。 |
| `lai_checker.py` | 源码语义的权威执行点，先于后端生成。 |
| `lai_backend.py` | 后端通用协议，保持 C/LLVM 选择可注入。 |
| `lai_c_backend.py` | 全量默认后端，负责 C 生成和构建。 |
| `lai_llvm_backend.py` | 受限 IR emitter，不用 `llvmlite`，不代表完整 LLVM 支持。 |
| `lai_clang.py` | 公共编译器进程调用层。 |
| `lai_stdlib.py` | 仅内部 C 输出运行时辅助，不增加 LAI 用户 API。 |
| `lai_int.py` | i32 常量边界和静态整数字面量树求值。 |

## 修改新语法的最小链路

用户可见语法先完成设计选择和测试，再按实际需求贯通 lexer、parser、`lai_ast.py`、`lai_checker.py`、C 后端、LLVM 能力边界与文档。只有当该语法明确属于 LLVM 子集时，才在 `lai_llvm_backend.py` 增加 lowering；否则保留清晰的“不支持”错误。所有路径最后以单元测试和真实 `clang` 示例验证。
