# LAI 项目根目录与模块地图

最后同步：2026-07-28。本文描述当前 v0.36 仓库布局；模块职责以当前源码为准。

## 源码模块

| 路径 | 职责 |
| --- | --- |
| `lai_compiler.py` | 词法、递归下降解析、文件编译流程、CLI；包含比较 > `not` > `and` > `or` 的逻辑层。 |
| `lai_ast.py` | 共享 AST：`Program`、语句节点、表达式节点，包括 `LogicalNotExpr` 与 `LogicalExpr`。 |
| `lai_core.py` | `LaiCompileError` 与核心名称规则。 |
| `lai_checker.py` | 语义/类型检查；逻辑 operand 和结果严格为 `bool`，不做 truthiness。 |
| `lai_backend.py` | 不可变的通用 `Backend` 描述符。 |
| `lai_clang.py` | C 与 LLVM 路径复用的 `clang` 调用和既有错误措辞。 |
| `lai_c_backend.py` | 完整默认 C 代码生成；逻辑 AST 生成保留括号的 `!`、`&&`、`||`。 |
| `lai_llvm_backend.py` | 受限文本 LLVM IR；`LogicalNotExpr` 和 `LogicalExpr` 仍明确不支持。 |
| `lai_stdlib.py` | 内部 C preamble、字符串转义、`print` 输出辅助；不是用户标准库 API。 |
| `lai_int.py` | i32 边界和纯整数静态求值，支持静态零除数、边界和 step 检查。 |

## v0.36 发布基线

`and`、`or`、`not` 是保留关键字且没有符号源码别名；逻辑类型严格为 `bool`。`and` / `or` 从左到右短路，C lowering 使用带 AST 括号的 `!` / `&&` / `||`。下一版是 v0.37 运行时整数语义与安全，剩余队列为 v0.37-v0.44，共 8 个版本。

## 生成物与历史文件边界

- `build/` 是默认 C 编译生成目录；`build/main.c`、`build/main.exe` 都由编译器写出，不能手工维护或当作源代码。
- `examples/build/*.ll` 与 `examples/build/*.exe` 是 LLVM 示例的本地生成输出，通常未跟踪，不应提交。
- `hello.c`、`hello.exe` 是早期实验文件；没有明确任务时不要在其上扩展功能。
- `.ly` 是推荐源码扩展名；旧 `.lai` 暂可读取，但只作为历史兼容边界。
