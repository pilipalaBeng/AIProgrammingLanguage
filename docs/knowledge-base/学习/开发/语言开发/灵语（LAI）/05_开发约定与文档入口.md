## 接手顺序

1. 阅读 `docs/ai/active-context.md`、`project-brief.md`、`architecture-map.md`、`module-index.md`、`conventions.md`。
2. 确认 `README.md`、当前源码和测试是否与上下文一致；当前版本应为 v0.38。
3. 处理既有版本时读对应 `docs/superpowers/specs/` 与 `docs/superpowers/plans/`；新版本先建立设计，再开始实现。
4. 修改语法或语义时以“测试 -> 前端/AST（如需要）-> checker -> 后端（如需要）-> 文档”的顺序闭环，并保留实验性 LLVM 的能力边界。

## 验证要求

至少运行完整单元测试；涉及可执行路径时，还应运行受影响的 C/LLVM 示例：

```powershell
python -m unittest discover -v
python lai_compiler.py main.ly --run
python lai_compiler.py examples/basic_comparisons.ly --run
python lai_compiler.py examples/boolean_logic.ly --run
python lai_compiler.py examples/runtime_integer_safety.ly --run
python lai_compiler.py examples/general_early_return.ly --run
python lai_compiler.py examples/general_early_return.ly --backend llvm
python lai_compiler.py examples/unary_integer.ly --backend llvm --run
python lai_compiler.py examples/llvm_minimal.ly --backend llvm --run
python lai_compiler.py examples/llvm_arithmetic.ly --backend llvm --run
```

报告时分开说明：源码/静态检查、单元测试、端到端 C 验证、端到端 LLVM 边界验证，以及因环境未执行的项。`clang` 不在 `Path` 或 Windows 链接环境缺失时，端到端失败只说明环境需要排查，不能据此虚构编译器结论。

## v0.38 发布事实

共享 checker 已实现 `fallthrough`、`return`、`break`、`continue`、`diverge` 的路径级组合，支持 guard clause，要求返回值函数所有可达路径返回，并报告第一条不可达语句。静态 `while true` 证明只识别 `true` 及其括号，普通循环仍保守；发散不能代替返回。

v0.37 的 checked i32 能力继续有效：纯静态零除和中间溢出在编译期诊断，动态 C 运算失败写 `stderr` 后以 `EXIT_FAILURE` 退出；`for` 三值单次求值、动态正 step、i32 上界范围完成和 collision-free 内部前缀均保留。

`examples/general_early_return.ly` 的 C 输出是 `-1`、`0`、`1`、`7`、`8`；LLVM 在第 1 行因 `FunctionDef` 不支持而拒绝。发布基线为 399 项单元测试通过。裸/void/main return、通用常量折叠、静态非空 `for` 证明、数组和 LLVM 控制流仍未实现。

## 生成物边界

- `build/` 是生成目录，不能手工维护 `build/main.c`。
- `examples/build/*.ll`、`examples/build/*.exe` 是本地 LLVM 示例生成物，不提交。
- `.exe` 只作本机验证证据，不等同于源代码变更。
- 保留并行或用户已有改动，只暂存本任务明确的文件。
