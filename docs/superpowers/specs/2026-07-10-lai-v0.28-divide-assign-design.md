# LAI v0.28 Divide Assignment Design

## Goal

Add minimal integer `/=` assignment sugar to LAI v0 while reusing the ordinary
division rules introduced in v0.27.

## Scope

v0.28 adds `name /= expr` statements:

```lai
let count = 8
count /= 2
count /= half(8)
count /= (6 / 2)
```

`/=` is valid anywhere the current statement grammar already accepts
assignments:

- top-level function bodies
- `if` / `else if` / `else` bodies
- `while` bodies
- `for` bodies

The left side must be an existing `int` variable or parameter. The right side
must be an `int` expression using the currently supported expression syntax,
including function calls, parentheses, addition, subtraction, multiplication,
and division.

## Semantics

`name /= expr` is statement sugar for:

```lai
name = name / expr
```

It follows the same integer division behavior as ordinary `/`: `int / int`
returns `int` and currently uses C integer division semantics.

`/=` does not introduce assignment expressions. It produces no value and can
only appear as a statement.

## Static Division By Zero

The compiler rejects obvious static zero divisors:

```lai
count /= 0
count /= (0)
```

Both forms report:

```text
line N: division by zero
```

Dynamic runtime checks are still out of scope. For example, `count /= value`
is accepted if `value` is an `int`, even if the runtime value might be zero.

## AST

Add `DivideAssignStmt` in `lai_ast.py` beside the existing compound assignment
nodes:

```python
@dataclass(frozen=True)
class DivideAssignStmt(Stmt):
    name: str
    value: Expr
    line: int
```

`DivideAssignStmt` is shared by parser, checker, and C backend.
`lai_compiler.py` continues to re-export it for compatibility with tests and
older scripts.

## Lexer And Parser

Keep `//` as line comments. Tokenize `/=` as `SLASH_EQUAL` after the comment
check and before falling back to the single-character `SLASH` token for
ordinary division.

Parsing mirrors `+=`, `-=`, and `*=`:

```text
NAME SLASH_EQUAL expr
```

The parser should keep the right-hand expression behavior identical to existing
compound assignment values.

## Type Checking

The checker validates:

- The target name exists in the current symbol table.
- The target type is `int`.
- The right-hand expression type is `int`.
- The right-hand expression is not an obvious static zero.

Suggested errors:

```text
line N: unknown variable: name
line N: cannot use /= with name of type string
line N: /= value must be int, got bool
line N: division by zero
```

## C Backend

Generate readable C using explicit assignment:

```c
count = count / 2;
```

This keeps generated output aligned with the existing `+=`, `-=`, and `*=`
lowering style.

## Tests

Add tests for:

- Tokenizing `/=` without breaking `//` comments.
- C generation for `count /= 2`.
- Right-hand expressions such as function calls and `(6 / 2)`.
- Function parameters using `/=`.
- `/=` inside loops.
- Parser construction of `DivideAssignStmt`.
- Unknown target rejection.
- Non-`int` target rejection.
- Non-`int` value rejection.
- Static zero and grouped static zero rejection.
- Module re-exports from compiler, checker, and backend.

## Non-Goals

v0.28 does not add:

- `%` or `%=`
- `count++`
- floating-point numbers
- negative integers or unary minus
- dynamic runtime division-by-zero checks
- assignment expressions
- full operator precedence
- LLVM IR changes
