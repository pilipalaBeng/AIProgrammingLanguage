# LAI v0.14 Branch Return Flow Design

最后更新：2026-07-09

## 目标

v0.14 补齐 v0.13 留下的返回控制流短板：带返回值函数除了可以用最后一条顶层 `return expr` 结束，也可以用完整的 `if / else if / else` 分支保证所有路径都返回。

示例：

```lai
fn grade(score: int) -> string {
    if score > 90 {
        return "A"
    } else if score > 80 {
        return "B"
    } else {
        return "C"
    }
}
```

## 范围

包括：

- 允许 `return expr` 出现在返回值函数的 `if` / `else if` / `else` 分支中。
- 检查返回值函数的最后一条顶层语句是否保证返回。
- 检查分支内 `return expr` 的类型必须匹配函数返回类型。
- 保持无返回值函数和 `main` 中禁止 `return`。
- 保持 `else if` 继续用嵌套 `IfStmt` 表示，不新增 AST 节点。

不包括：

- 不支持通用早退，例如顶层 `return` 后继续写语句。
- 不支持没有 `else` 的 `if` 作为完整返回路径。
- 不支持循环中的 `return` 分析。
- 不新增 `while`、`for`、`break`、`continue`。
- 不新增括号表达式或完整运算符优先级。

## 语义规则

返回值函数的最后一条顶层语句必须满足以下任一条件：

- 是 `ReturnStmt`。
- 是一个 `IfStmt`，并且 then 分支和 else 分支都保证返回。

`IfStmt` 保证返回的条件：

- `then` 分支最后一条语句保证返回。
- 必须存在 `else` 分支。
- `else` 分支最后一条语句保证返回；`else if` 链通过嵌套 `IfStmt` 自然递归处理。

分支内允许先写普通语句，再以 `return` 或完整返回 `if` 结束。`return` 后面继续写语句仍然报错，避免 v0.14 过早引入不可达代码分析。

## 架构影响

### AST

不新增 AST 节点。继续复用：

- `ReturnStmt`
- `IfStmt`

### Parser

parser 已经可以解析分支内的 `ReturnStmt`，本版本不需要改语法解析。

### Checker

主要改动在 `lai_checker.py`：

- 为返回值函数新增递归的“语句是否保证返回”检查。
- 在返回值函数中，允许 `return` 出现在最终返回路径的块内。
- 在无返回值函数和 `main` 中，继续使用现有检查路径禁止任何 `return`。

### C Backend

C backend 已经能生成 `return value;` 和嵌套 `if/else`。本版本不需要新增 C 代码生成规则，只需要通过 checker 放行合法程序。

## 错误行为

保留并扩展现有错误风格：

- 返回值函数没有保证返回：`line N: function name must end with return`
- `return` 后还有同一块内语句：`line N: return must be the final statement in its block`
- 返回类型不匹配：`line N: return type must be int, got string`
- 无返回值函数或 `main` 中使用 `return`：`line N: return is only allowed in functions with return type`

## 测试

新增测试覆盖：

- `if / else` 两侧都 `return`。
- `else if` 链每个路径都 `return`。
- 分支内可以先 `let` / `print` 再 `return`。
- 缺少 `else` 时拒绝。
- 某个分支没有返回时拒绝。
- 分支内返回类型不匹配时拒绝。
- 分支内 `return` 后继续写语句时拒绝。
- 无返回值函数和 `main` 中的分支 `return` 继续拒绝。
