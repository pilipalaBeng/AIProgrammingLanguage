# LAI v0.40 第一阶段：数组元素修改

日期：2026-09-07。用户已确认方案 A，元素修改已实现并通过测试。v0.40 的长度 API 和遍历仍未实现，本次不宣布整个版本完成。

## 语法与范围

```lai
let scores: int[] = [90, 95, 100]
scores[0] = 80
scores[0] += 5
scores[0] -= 1
scores[0] *= 2
scores[0] /= 2
scores[0] %= 10
```

- `int[]`、`string[]`、`bool[]` 都允许 `=`，右侧必须与元素类型一致。
- `+= -= *= /= %=` 仅接受 int 元素与 int 右值，沿用 checked i32 行为。不引入字符串拼接。
- 数组长度不变，零基 int 索引、负数非法、静态越界编译错误和动态越界运行错误继续有效。
- 索引目标仍限局部数组名及括号形式，如 `(scores)[0]`；多维、数组参数/返回、整体赋值/复制不开放。
- 更新是语句，不是表达式；不加入链式赋值、自增、方法、`set` 函数或新的关键字。
- 候选 A 下标赋值与既有读取/标量赋值一致，采用成熟 C# 数组写法；候选 B 显式 `set(array, index, value)` 操作名直接，但会引入额外 API 规则，用户选择 A。

## 求值与失败顺序

1. 计算目标索引一次，并完成上下界检查。
2. 对复合赋值，读取该位置旧值一次。
3. 计算右值一次；右值内部沿用现有表达式规则，包括布尔短路。
4. 普通赋值写入右值；复合赋值经过既有 checked i32 helper 得到结果后写入。

动态索引失败时不执行右侧；右值失败或算术失败时不写入。编译期仍检查所有可达源码中的静态错误，不以运行时短路或前序失败隐藏类型错误。`/=`、`%=` 的纯静态零右值在编译期拒绝；旧值不作跨语句常量传播，因此与旧值有关的溢出走 runtime。

## 模块设计

- `lai_ast.py` 新增不可变 `IndexAssignStmt(target: IndexExpr, operator: str, value: Expr, line: int)`，不改旧赋值节点构造。`lai_compiler.py` 兼容导出。
- parser 将当前专门拒绝索引更新的分支改为解析该节点，右值复用完整表达式解析。将索引声明、读取和修改保持不同 helper。
- checker 用 `_infer_index_type` 复用目标/索引校验，再检查操作符和右值，语句正常 fallthrough；不修改符号类型或数组长度。
- C 后端先把已经过检查的元素地址保存到 collision-free 指针临时量，复合赋值再保存旧值。每个阶段为独立 C 完整表达式，保证执行顺序。

```c
int* slot = &storage[checked_index(index(), length, line)];
int old_value = *slot;
int value = rhs();
*slot = checked_add(old_value, value, line);
```

字符串 slot 类型为 `const char**`，替换指向既有字符串内容的指针，不修改字符串字节。临时指针仅存在生成 C 中，不是用户语言新增指针能力。

默认 C 后端支持完整已实现能力，实验性 LLVM 保持旧子集。有效数组仍报明确后端能力错误，不绕过共享检查。
