# LAI v0.30 Modulo Assignment Design

## Goal

Add `%=` modulo assignment as the next small arithmetic convenience after
ordinary `%` expressions.

## Scope

v0.30 adds statement-level modulo assignment:

```lai
let count = 7
count %= 3
print(count)
```

It is valid in the same statement positions as the existing `+=`, `-=`, `*=`,
and `/=` statements:

- function bodies
- `main`
- `if` / `else if` / `else` blocks
- `while` and `for` loop bodies

`count %= expr` is equivalent to:

```lai
count = count % expr
```

The right-hand side can be any expression that is already accepted as an
integer expression, including names, calls, arithmetic, and parenthesized
groups.

## Semantics

The left side must name an existing `int` variable or parameter. The right side
must evaluate to `int`.

The compiler rejects obvious static zero right-hand operands:

```lai
count %= 0
count %= (0)
```

Both produce:

```text
line N: modulo by zero
```

Dynamic runtime modulo-by-zero checks are still out of scope.

## AST

Add `ModuloAssignStmt` beside the existing compound assignment statement nodes:

```python
@dataclass(frozen=True)
class ModuloAssignStmt(Stmt):
    name: str
    value: Expr
    line: int
```

`ModuloAssignStmt` is shared by parser, checker, and C backend. The compatibility
exports in `lai_compiler.py` should expose it in the same way as
`DivideAssignStmt`.

## Lexer And Parser

Tokenize `%=` as `PERCENT_EQUAL` before falling through to single-character `%`.

Parser behavior:

- If a statement starts with a name token followed by `PERCENT_EQUAL`, parse it
  as `ModuloAssignStmt`.
- The right-hand value uses the existing `self._parse_expr(allow_string=False,
  allow_name=True)` path.
- `%=` remains a statement, not an expression. v0.30 does not add assignment
  expressions.

Ordinary `%` expression parsing remains unchanged: `%` still shares precedence
with `*` and `/`.

## Type Checking

Checker rules match `/=` with modulo-specific wording:

- unknown target: `line N: unknown variable: count`
- non-`int` target: `line N: cannot use %= with count of type string`
- non-`int` value: `line N: %= value must be int, got bool`
- static zero value: `line N: modulo by zero`

The static zero helper already handles grouped zero through `GroupExpr`.

## C Backend

Generate readable C:

```c
count = count % expr;
```

The backend keeps the same defensive checks as the semantic checker so direct
backend calls still fail clearly.

## Tests

Add tests for:

- Tokenizing `%=`.
- `count %= 3` generating `count = count % 3;`.
- RHS integer expressions such as calls and grouped modulo/division.
- `%=` on function parameters.
- `%=` inside loops.
- `ModuloAssignStmt` parser AST and module re-exports.
- Unknown target variable.
- Non-`int` target variable.
- Non-`int` right-hand value.
- Static `%=` by zero, including grouped zero.

## Non-Goals

v0.30 does not add:

- new `%` precedence behavior
- assignment expressions
- `count++`
- floating-point numbers
- negative integers or unary minus
- dynamic runtime modulo-by-zero checks
- logical operators
- full operator precedence
- LLVM IR changes
