# LAI v0.34 负数与一元整数表达式设计

日期：2026-07-23
状态：已完成。2026-07-23 已通过完整单元测试和 C/LLVM 真实 clang 示例验证。

## 1. 背景

LAI v0.33 已支持整数加、减、乘、除、取模和括号表达式，但 `-` 只能作为
二元减法使用，下面这些常见写法仍不能解析：

```lai
let temperature = -5
let opposite = -temperature
print(-(2 + 3))
print(2 * -3)
```

v0.34 补齐负数以及一元 `+` / `-`。本版继续保持小范围：只处理 `int`，
不同时引入浮点数、自增自减、倒序循环或完整运行时溢出检查。

## 2. 已确认语法

采用完整前缀一元运算方案：

```lai
let negative = -5
let positive = +5
let opposite = -negative
let grouped = -(2 + 3)
let product = 2 * -3
let restored = --5
```

语义如下：

- `-expr` 计算 `expr` 的相反数。
- `+expr` 保留 `expr` 的整数值。
- 一元运算可递归组合，因此 `--5` 表示 `-(-5)`，结果为 `5`。
- `--` 在 v0.34 中不是自减运算符；`count--` 仍不受支持。
- 一元运算可以出现在任何已有整数表达式位置，包括变量初始化、赋值、
  复合赋值右侧、函数参数、返回值、打印、比较以及循环起止值。
- 静态可判定的 `INT_MIN` 再取负会报溢出；本版不增加动态运行时溢出检查。

## 3. 候选方案结论

设计阶段比较过三种方案：

1. 同时支持一元 `+` 和 `-`。
2. 只支持一元 `-`。
3. 只把符号并入整数字面量，不支持 `-name` 或 `-(expr)`。

最终选择方案 1。它和 C、C#、Rust、Python 等成熟语言的前缀运算习惯接近，
表达能力完整，也能为后续其他一元运算保留清楚的解析层。方案 2 会留下不完整的
整数一元运算；方案 3 会把负号错误地限制为词法细节，无法自然处理变量和括号表达式。

## 4. 词法与 AST

词法层不增加 token。现有 `PLUS` 和 `MINUS` 同时供二元加减与一元正负使用，
由 parser 根据表达式位置决定含义。

`lai_ast.py` 新增统一节点：

```python
@dataclass(frozen=True)
class UnaryExpr(Expr):
    operator: str
    operand: "Expr"
```

`operator` 在 v0.34 的源码路径中只会是 `+` 或 `-`。使用一个统一节点可以避免
为正号和负号创建两个结构相同的节点，也与现有 `CompareExpr.operator` 风格一致。
checker 和 backend 仍需拒绝直接构造的未知 operator，防止非法 AST 静默通过。

负号不并入 `IntExpr`。例如 `-5` 的 AST 是：

```text
UnaryExpr("-", IntExpr(5))
```

这样 `-name`、`-(2 + 3)` 和 `--5` 都使用同一条语义路径，而不是依赖源码字符串截取。

## 5. 解析与优先级

表达式语法在乘除层与基础表达式层之间新增 `unary`：

```text
expr       := add_expr (("<" | ">" | "==") add_expr)?
add_expr   := multiply_expr (("+" | "-") multiply_expr)*
multiply_expr := unary_expr (("*" | "/" | "%") unary_expr)*
unary_expr := ("+" | "-") unary_expr | primary_expr
primary_expr := literal | name | call | "(" expr ")"
```

因此优先级从高到低为：

1. 基础表达式和括号。
2. 一元 `+`、`-`。
3. `*`、`/`、`%`。
4. 二元 `+`、`-`。
5. `<`、`>`、`==`。

示例：

- `-2 * 3` 解析为 `(-2) * 3`。
- `2 * -3` 解析为 `2 * (-3)`。
- `-(2 * 3)` 先计算括号，再取相反数。
- `-2 + 3` 解析为 `(-2) + 3`。
- `--5` 解析为 `-(-5)`。

括号继续只改变分组，不改变类型。

## 6. 类型与错误规则

一元 `+` 和 `-` 的 operand 必须是 `int`，结果也是 `int`。

合法示例：

```lai
let count = 3
print(-count)
print(+add(1, 2))
print(-(1 + 2))
```

非法示例：

```lai
print(-"LAI")
print(+true)
```

错误保持带源码行号，并明确 operator 与实际类型：

```text
line 2: unary - operand must be int, got string
line 3: unary + operand must be int, got bool
```

缺少 operand 时继续使用 parser 的位置错误，例如 `print(-)` 报
`expected expression`。

## 7. 整数范围

LAI v0.34 把 `int` 源码字面量边界明确为有符号 `i32`：

```text
-2147483648 .. 2147483647
```

普通 `IntExpr` 仍保存无符号数字 token 的值，因此：

- `2147483647` 合法。
- `2147483648` 单独出现时非法。
- `+2147483648` 非法。
- `-2147483648` 合法，它是最小 `i32` 的标准写法。
- `-2147483649` 非法。
- `-(2147483648)` 与多层等价括号也按最小 `i32` 处理。
- `-+2147483648` 非法；最小值特例只匹配负号直接包裹的正幅值及其括号。
- `-(-2147483648)` 非法，因为它的数学结果超出有符号 `i32` 上界。

checker 必须在递归检查普通 `IntExpr` 前识别一元负号的最小值特例，不能先把
它的幅值 `2147483648` 当作独立正整数接受。

静态可求值的一元负号如果对 `INT_MIN` 再取负，checker 报：

```text
line 2: integer unary negation overflow
```

本版规范源码字面量范围，并拒绝上述静态一元溢出。其他算术仍维持当前边界：LLVM
后端沿用 v0.33 的无标记 `i32` 回绕规则，C 后端使用现有 C 整数运算行为。
变量或函数调用在运行时产生 `INT_MIN` 后再取负仍属于动态运行时溢出缺口，
不在 v0.34 增加运行时保护。

## 8. 静态零与循环步长

现有除零和取模零检查需要识别一元表达式：

```lai
print(8 / -0)
print(8 % +0)
```

二者必须分别报 `division by zero` 和 `modulo by zero`。括号与多层一元运算
不能绕过静态零检查。

负数可以作为 `for` 的起点和终点：

```lai
for i from -2 to 2 {
    print(i)
}
```

v0.34 不引入倒序循环，显式可静态求值的非正步长仍需拒绝：

```lai
for i from 3 to 0 step -1 {
    print(i)
}
```

错误沿用当前措辞：

```text
line 1: for step must be greater than 0
```

checker 增加一个只处理纯整数字面量树的静态求值 helper，覆盖 `IntExpr`、
`GroupExpr`、`UnaryExpr` 和已有五种整数算术节点。遇到变量或调用时返回“未知”，
不猜测运行时值。它用于：

- 识别带括号或一元符号的静态零除数。
- 拒绝 `step -1`、`step -(1 + 1)`、`step 1 - 2`。
- 拒绝 `step -0`、`step 1 - 1`。
- 识别静态 `INT_MIN` 一元取负溢出。

静态求值中的除法按向零截断，取模符号跟随被除数，与既有 C/LLVM 整数语义一致。
遇到零除数或无法安全求值的节点时，由原有错误路径处理或返回“未知”，不让 helper
替代正式类型检查。动态表达式在运行时变为非正步长的问题仍属于现有运行时校验缺口。

## 9. C 后端

C 后端递归生成 unary operand，并用括号保护优先级：

```lai
print(-(2 + 3) * 4)
```

可生成等价的可读 C 表达式：

```c
printf("%d\n", (-(2 + 3)) * 4);
```

`-2147483648` 不能依赖 C 编译器先把正幅值当作 `int`，应输出等价且边界明确的
表达式，例如：

```c
(-2147483647 - 1)
```

一元正号仍保留在生成结果中，方便测试确认 AST 没有被误当成二元加法。
静态 `INT_MIN` 再取负在 checker 阶段被拒绝，因此不会输出已知会触发 C 有符号
溢出的表达式。动态 `INT_MIN` 一元取负仍保留为本版明确记录的运行时限制。

## 10. LLVM 后端

实验性 LLVM 后端把 `UnaryExpr` 纳入现有顶层整数 `print` 子集。

- 一元 `+` 直接返回 operand，不生成冗余指令。
- 一元 `-` 通常生成 `sub i32 0, operand`。
- lowering 继续携带 `(LLVM operand, synchronized i32 value)`，一元负号同步更新
  有符号 `i32` 值。
- `-2147483648` 使用合法的 `i32` 常量边界路径，不能先尝试 lowering 非法正常量
  `2147483648`。
- `-(-2147483648)` 在进入 lowering 前由 checker 报静态一元溢出。
- 未知 unary operator 或非法直接 AST 必须产生明确能力/内部边界错误。

示意 IR：

```llvm
%value0 = sub i32 0, 5
```

变量、赋值、比较、布尔、字符串、控制流和用户函数仍不属于 LLVM v0.34 子集。

## 11. 测试范围

### Lexer 与 parser

- 复用现有 `PLUS`、`MINUS` token。
- `-5`、`+5`、`-name`、`-(expr)`、`2 * -3`、`--5` 的 AST。
- 一元优先级与括号分组。
- `print(-)` 等不完整表达式错误。

### AST 与模块边界

- `UnaryExpr` 的结构、不可变性和兼容导出。
- parser、checker、C backend、LLVM backend 使用同一个 AST 节点类型。

### Checker 与 C 后端

- 所有已有整数表达式位置可使用 unary。
- string、bool 和无返回值调用被拒绝。
- `i32` 字面量上下界。
- `-+2147483648` 被拒绝，`-(-2147483648)` 报静态一元溢出。
- `-0` / `+0` 除零和取模零检查。
- `step -1`、`step -(1 + 1)`、`step 1 - 2`、`step -0` 和 `step 1 - 1`
  被拒绝；负起止值可用。
- 生成 C 保留一元运算和正确括号。
- checker 和 C backend 拒绝直接构造的未知 `UnaryExpr.operator`。

### LLVM 后端

- 一元负号生成 `sub i32 0, value`。
- 一元正号不生成冗余运算。
- 嵌套一元运算、优先级和 `-2147483648`。
- 负数除法与取模保持截断到零及余数跟随被除数符号。
- 直接负数字面量路径下，`-2147483648 / -1` 与 `% -1` 继续报 LLVM signed
  division/remainder overflow。
- 直接构造的越界或非法 unary AST 被拒绝。

### 端到端

- 新增一个同时可由 C 和 LLVM 后端运行的 unary 示例。
- 运行完整单元测试。
- 运行默认 C 示例、LLVM 最小示例、LLVM 算术示例和 unary 示例。

## 13. 非目标

v0.34 不实现：

- `count++`、`count--`
- 倒序 `for` 或正式负步长语义
- 浮点数及其一元运算
- 布尔非运算 `!`
- 位运算取反
- 动态运行时除零检查
- 通用运行时整数溢出检查
- LLVM 变量、赋值、比较、控制流和用户函数
- 完整的所有运算符优先级体系

下一版仍按路线图进入 v0.35 基础比较能力补全，并在实施前单独确认运算符集合与类型规则。
