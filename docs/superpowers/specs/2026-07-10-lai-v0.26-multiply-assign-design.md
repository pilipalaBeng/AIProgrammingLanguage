# LAI v0.26 Multiply Assignment Design

## Goal

Add minimal integer `*=` assignment sugar to LAI v0 while reusing the existing
compound-assignment pipeline proven by `+=` and `-=`.

## Scope

v0.26 adds `name *= expr` statements:

```lai
let count = 3
count *= 2
count *= add(1, 2)
count *= (2 + 3)
```

`*=` is valid anywhere the current statement grammar already accepts
assignments:

- top-level function bodies
- `if` / `else if` / `else` bodies
- `while` bodies
- `for` bodies

The left side must be an existing `int` variable or parameter. The right side
must be an `int` expression using the currently supported expression syntax,
including function calls, parentheses, addition, subtraction, and
multiplication.

## Semantics

`name *= expr` is statement sugar for:

```lai
name = name * expr
```

It does not introduce assignment expressions. It produces no value and can only
appear as a statement.

## AST

Add `MultiplyAssignStmt` in `lai_ast.py` beside the existing compound assignment
nodes:

```python
@dataclass(frozen=True)
class MultiplyAssignStmt(Stmt):
    name: str
    value: Expr
    line: int
```

`MultiplyAssignStmt` is shared by parser, checker, and C backend.
`lai_compiler.py` continues to re-export it for compatibility with tests and
older scripts.

## Lexer And Parser

Tokenize `*=` as `STAR_EQUAL` before falling back to the single-character
`STAR` token for ordinary multiplication.

Parsing mirrors `+=` and `-=`:

```text
NAME STAR_EQUAL expr
```

The parser should keep the right-hand expression behavior identical to ordinary
assignment and existing compound assignment values.

## Type Checking

The checker validates:

- The target name exists in the current symbol table.
- The target type is `int`.
- The right-hand expression type is `int`.

Suggested errors:

```text
line N: unknown variable: name
line N: cannot use *= with name of type string
line N: *= value must be int, got bool
```

## C Backend

Generate readable C using explicit assignment:

```c
count = count * 2;
```

This keeps generated output aligned with the existing `+=` and `-=` lowering
style.

## Tests

Add tests for:

- Tokenizing `*=`.
- C generation for `count *= 2`.
- Right-hand expressions such as `add(1, 2)` and `(2 + 3)`.
- Function parameters using `*=`.
- `*=` inside loops.
- Parser construction of `MultiplyAssignStmt`.
- Unknown target rejection.
- Non-`int` target rejection.
- Non-`int` value rejection.
- Module re-exports from compiler, checker, and backend.

## Non-Goals

v0.26 does not add:

- `/` or `/=`
- `%` or `%=`
- `count++`
- negative integers or unary minus
- assignment expressions
- string repetition
- full operator precedence
- LLVM IR changes
