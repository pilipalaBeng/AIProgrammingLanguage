# LAI v0.33 LLVM Integer Arithmetic Design

日期：2026-07-23

状态：已实现并验证

## 目标

v0.33 在不新增 LAI 源码语法的前提下，让实验性文本 LLVM 后端支持
`print(...)` 中已有的完整整数算术表达式：

```lai
fn main() {
    print(1 + 2)
    print(5 - 2)
    print(2 * 3)
    print(8 / 2)
    print(7 % 3)
    print((2 + 3) * 4)
}
```

默认 C 后端保持完整且不改变。LLVM 后端继续使用文本 IR 和系统 `clang`，
不引入 `llvmlite`。

## 已确认的范围

v0.33 支持 LLVM lowering：

- `IntExpr`
- `AddExpr`
- `SubtractExpr`
- `MultiplyExpr`
- `DivideExpr`
- `ModuloExpr`
- `GroupExpr`

这些表达式仅作为顶层 `PrintStmt.value` 使用。空 `main` 和单个整数字面量
`print` 的 v0.32 行为继续保留。

v0.33 不支持 LLVM lowering：

- `let` 和变量读取
- 普通赋值及复合赋值
- 比较和布尔表达式
- `if`、`while`、`for`
- 用户函数、参数和返回值
- 字符串输出
- 负数字面量
- `llvmlite`
- LAI 专用低层 IR

这些限制只属于实验性 LLVM 后端。默认 C 后端仍支持当前完整 LAI v0.32
语言表面。

## 方案比较

### 方案 A：递归 lowering 到 LLVM 临时值

递归读取共享 AST，为每个非字面量运算生成一个 LLVM SSA 风格临时值。

优点：

- 真正验证 LLVM 的 `add`、`sub`、`mul`、`sdiv` 和 `srem` 指令。
- AST 已经包含优先级和括号结构，后端不需要重复解析。
- 能自然延伸到后续变量和控制流 lowering。
- 范围小，仍可用可读文本断言测试。

缺点：

- 需要管理唯一临时值编号。
- 比编译期直接算出常量多一点状态。

### 方案 B：Python 编译期常量折叠

在 LLVM 后端中直接计算表达式结果，再继续输出整数常量 `printf`。

优点是实现最短；缺点是没有验证 LLVM 算术指令，而且未来变量表达式需要
推翻这一实现。

### 方案 C：先建立 LAI 专用低层 IR

先将 AST 转为自有指令层，再从该层生成 LLVM IR。

扩展性较强，但当前只有一个极小 LLVM 子集，引入新 IR 会增加无必要的节点、
校验和测试层。

## 决策

采用方案 A：递归 lowering 到 LLVM 临时值。

不采用编译期常量折叠作为主实现，也不在 v0.33 引入 LAI 专用低层 IR。

## 后端结构

`lai_llvm_backend.py` 增加一个仅负责 `main` 函数体发射的小型状态对象，例如
`_LlvmMainEmitter`。它拥有：

- `body_lines: list[str]`：按执行顺序保存 LLVM 指令。
- `next_value_index: int`：分配 `%value0`、`%value1` 等唯一临时值。
- `lower_int_expr(expr, line) -> tuple[str, int]`：返回 LLVM 操作数和该表达式
  按普通 `i32` 指令得到的同步计算值。同步值只用于拒绝 LLVM 未定义行为，
  不替代真实 IR 指令。
- `emit_print(statement, print_index) -> None`：lowering 表达式后追加 `printf`。

`generate_llvm(program)` 继续面向直接调用者执行一次 `check_program(program)`；
`LLVM_BACKEND.emit` 继续指向不重复检查的内部生成入口。这样
`compile_source(source, LLVM_BACKEND)` 仍只执行一次语义检查。

## 表达式 lowering

### 整数字面量

`IntExpr(42)` 直接返回 LLVM 操作数 `42`，不生成临时指令。

每个递归位置都必须验证：

- `type(value) is int`，明确排除 Python `bool` 和 `float` 载荷。
- 值位于 `0..2147483647`。

### 括号

`GroupExpr` 不生成独立 LLVM 指令，只递归 lowering 内部表达式。括号产生的
运算顺序已经保存在 AST 结构中。

### 二元和多项运算

映射规则：

| LAI AST | LLVM 指令 |
| --- | --- |
| `AddExpr` | `add i32` |
| `SubtractExpr` | `sub i32` |
| `MultiplyExpr` | `mul i32` |
| `DivideExpr` | `sdiv i32` |
| `ModuloExpr` | `srem i32` |

`AddExpr.terms` 和 `MultiplyExpr.factors` 按从左到右的顺序折叠。二元节点先
lowering 左侧，再 lowering 右侧，然后分配一个新 `%valueN`。

使用 `sdiv` 和 `srem`，因为 LAI 的 `int` 是有符号整数语义，减法结果可以为负。
不添加 `nsw`、`nuw` 或 `exact` 标记。

lowering 每个节点时同时计算该节点的普通 `i32` 结果。`add`、`sub`、`mul`
按 32 位补码回绕；`sdiv` 向零截断；`srem` 与被除数同号。该同步计算不把
表达式折叠成字面量，生成的 IR 仍包含每个实际算术指令。

例如：

```lai
print(2 + 3 * 4)
```

生成的函数体核心为：

```llvm
%value0 = mul i32 3, 4
%value1 = add i32 2, %value0
%print0 = call i32 (ptr, ...) @printf(ptr @.fmt.int, i32 %value1)
```

而：

```lai
print((2 + 3) * 4)
```

先生成 `add`，再生成 `mul`。

## 除零和溢出边界

v0.33 先复用现有 checker 的显式除零规则，再由 LLVM lowering 利用同步计算值
拒绝当前常量子集中会触发 LLVM 未定义行为的表达式。这里不修改共享 checker，
也不改变默认 C 后端的既有行为。

- 显式 `0`、`(0)` 仍由 checker 报 `division by zero` 或 `modulo by zero`。
- 计算后除数为零，例如 `8 / (1 - 1)` 或 `7 % (3 - 3)`，由 LLVM 后端报
  相同的对应错误，不生成 IR。
- `sdiv i32 -2147483648, -1` 和 `srem i32 -2147483648, -1` 在 LLVM 中属于
  未定义行为。虽然当前语法没有负数字面量，但减法可以构造这两个操作数；
  LLVM 后端分别报 `LLVM backend signed division overflow` 和
  `LLVM backend signed remainder overflow`。
- 普通 `add`、`sub`、`mul` 不添加 `nsw` 或 `nuw`，因此在 LLVM 后端按
  32 位补码回绕。v0.33 会测试这一行为，但暂不把它定义为 C/LLVM 后端共同的
  LAI 整数溢出承诺；统一整数溢出语义留待独立设计。
- v0.33 不新增动态运行时除零检查。当前 LLVM 子集没有变量或调用，因此所有
  已允许整数表达式都能在 lowering 时同步计算。

## 能力错误

顶层语句仍只允许 `PrintStmt`。`PrintStmt.value` 必须是本设计列出的整数表达式
节点之一。遇到尚未支持的有效表达式时，继续使用带行号的明确错误：

```text
line N: LLVM backend does not support <NodeName> yet
```

递归表达式中的非法直接 AST 载荷也必须在生成 IR 前被拒绝，不能输出
`i32 True`、`i32 1.0` 或超出范围的字面量。

## 示例

新增 `examples/llvm_arithmetic.ly`，不修改 v0.32 的
`examples/llvm_minimal.ly`：

```lai
fn main() {
    print(2 + 3 * 4)
    print((2 + 3) * 4)
    print(5 - 2)
    print(8 / 2)
    print(7 % 3)
}
```

运行命令：

```powershell
python lai_compiler.py examples/llvm_arithmetic.ly --backend llvm --run
```

预期程序输出：

```text
14
20
3
4
1
```

## 测试要求

测试至少覆盖：

- `LLVM_BACKEND` 原有描述符和 v0.32 最小输出兼容性。
- `add`、`sub`、`mul`、`sdiv`、`srem` 的实际 IR。
- `2 + 3 * 4` 的先乘后加指令顺序。
- `(2 + 3) * 4` 的先加后乘指令顺序。
- 多项加法、乘法和多个 `print` 的临时值唯一性。
- `8 / (1 - 1)` 和 `7 % (3 - 3)` 在 LLVM lowering 时拒绝。
- 普通 `add`、`sub`、`mul` 溢出按无标记 `i32` 指令回绕。
- 由减法构造的 `INT_MIN / -1` 和 `INT_MIN % -1` 被明确拒绝。
- 递归位置的 `bool`、`float` 和超出 `i32` 范围载荷拒绝。
- 现有语义错误优先于 LLVM 能力错误。
- `compile_source(..., LLVM_BACKEND)` 只检查一次。
- 默认 C 后端完整回归。
- `examples/llvm_minimal.ly` 继续输出 `42`。
- `examples/llvm_arithmetic.ly` 经真实 clang 构建并输出五个预期结果。
