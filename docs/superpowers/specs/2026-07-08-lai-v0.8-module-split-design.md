# LAI v0.8 编译器模块拆分设计

日期：2026-07-08

## 目标

v0.8 将 LAI / 灵语编译器从单文件继续拆分出更清晰的内部模块边界。

本版本不新增用户语法，而是把共享错误类型、语义检查和 C 后端从 `lai_compiler.py` 中分离出来。

## 范围

本版本支持：

- 新增 `lai_core.py`：
  - `LaiCompileError`
  - `NAME_RE`
- 新增 `lai_checker.py`：
  - `check_program(program)`
  - `collect_function_names(functions)`
- 新增 `lai_c_backend.py`：
  - `generate_c(program)`
  - 语句/表达式到 C 的内部转换 helper
- `lai_compiler.py` 继续保留：
  - token 定义和 `tokenize(source)`
  - parser 和 `parse_source(source)`
  - `compile_source(source)`
  - `compile_file(...)`
  - CLI `main(...)`
- `lai_compiler.py` 兼容导出 `LaiCompileError`、`check_program` 和 `generate_c`。

本版本不做：

- 不拆 AST 节点到独立文件。
- 不拆 lexer 或 parser 到独立文件。
- 不新增 `else`、循环、函数参数或返回值。
- 不改变 `.ly` 用户源码语法。
- 不改变生成 C 的行为。

## 设计说明

`lai_checker.py` 和 `lai_c_backend.py` 通过当前 AST 节点的结构工作，不反向导入 `lai_compiler.py`。
这样可以避免循环导入，同时保持未来继续拆出 AST 文件的空间。

`lai_compiler.py` 仍然重新导出旧入口，因此已有代码可以继续写：

```python
from lai_compiler import LaiCompileError, check_program, generate_c
```

新代码也可以直接导入拆分模块：

```python
from lai_checker import check_program
from lai_c_backend import generate_c
```

## 兼容性

v0.8 不改变已有合法 `.ly` 程序的行为。

示例程序端到端输出应保持：

```text
Hello LAI
JD
Hello from function
3
count is three
math works
```

## 测试

新增 `tests/test_lai_module_boundaries.py`，覆盖：

- `lai_compiler.LaiCompileError` 兼容导出 `lai_core.LaiCompileError`。
- `lai_compiler.check_program` 兼容导出 `lai_checker.check_program`。
- `lai_compiler.generate_c` 兼容导出 `lai_c_backend.generate_c`。
- 拆出的 checker 可以处理 parser 生成的 AST。
- 拆出的 C backend 可以处理 parser 生成的 AST。

同时保留原有编译器测试、标准库辅助测试和端到端验证。
