# LAI v0.22 Parenthesized Expressions Design

最后更新：2026-07-10

## 目标

v0.22 新增括号表达式，让用户可以显式分组已有表达式：

```lai
let value = (1 + 2)
let ok = (value == 3)
if (ok) {
    print("yes")
}
```

括号必须影响表达式分组。当前版本还没有 `-`、`*`、`/` 或完整运算符优先级，所以 v0.22 的重点不是新增数学能力，而是先把分组节点和解析边界打稳。

## 范围

包括：

- 在 `let`、`print`、`return`、函数实参、`if` 条件、`while` 条件、`for` 起点/终点/步长和赋值表达式中使用括号。
- 支持嵌套括号，例如 `((1 + 2))`。
- 支持用括号包住整数、字符串、布尔、变量、函数调用、加法和比较表达式。
- C 后端保留括号输出，例如 `(1 + 2)`。
- checker 直接使用括号内部表达式的类型。

不包括：

- 不新增普通减法、乘法、除法、负数或完整运算符优先级。
- 不改变现有 `+` 和比较表达式的优先级。
- 不支持空括号 `()`。
- 不支持跨行括号表达式；v0 仍然以换行结束语句。

## 语法规则

扩展 primary expression：

```text
primary_expr :=
    string
  | true
  | false
  | int
  | name
  | call_expr
  | "(" expr ")"
```

示例：

```lai
print((1 + 2))
let ready = (1 + 2) == 3
if (ready) {
    print("ok")
}
```

## 语义规则

- 括号表达式的类型等于内部表达式的类型。
- `print(("text"))` 仍是 `string`。
- `let count = (1 + 2)` 仍是 `int`。
- `let ready = (1 + 2) == 3` 仍是 `bool`。
- `if (1 + 2)` 仍然报 `if condition must be bool, got int`。
- `print(())` 报 `expected expression`。
- `print((1 + 2)` 报 `expected RPAREN`。

## 架构影响

### AST

新增：

- `GroupExpr(value: Expr)`

`GroupExpr` 只保存分组，不改变内部表达式含义。

### Parser

在 `_parse_primary_expr(...)` 中识别 `LPAREN`：

1. 读取内部 `_parse_expr(...)`。
2. 消费匹配的 `RPAREN`。
3. 返回 `GroupExpr(inner)`。

函数调用参数和 `print(...)` 外层括号继续由调用语法处理；表达式括号只在 primary expression 层处理。

### Checker

`_infer_expr_type(GroupExpr(...))` 返回内部表达式类型。

### C Backend

`_expr_to_c_value(GroupExpr(...))` 返回内部表达式类型和加括号的 C 表达式：

```c
(1 + 2)
```

## 测试要求

覆盖：

- token 中已有 `LPAREN` / `RPAREN` 可用于表达式。
- `print((1 + 2))` 生成 `printf("%d\n", (1 + 2));`。
- `let count = (1 + 2)` 生成 `int count = (1 + 2);`。
- `let ok = (1 + 2) == 3` 生成 `int ok = (1 + 2) == 3;`。
- `if (ok) { ... }` 生成 `if ((ok))` 或等价保留括号输出。
- 函数实参和返回值支持括号表达式。
- AST 中能看到 `GroupExpr`。
- `print((1 + 2)` 报 `expected RPAREN`。
- `print(())` 报 `expected expression`。
- `if (1 + 2)` 继续报非 bool 条件。
