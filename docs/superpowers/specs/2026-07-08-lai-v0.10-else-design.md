# LAI v0.10 Else 语法设计

最后更新：2026-07-08

## 背景

v0.9 已经把 AST 节点拆到 `lai_ast.py`，parser、checker 和 C backend 共享同一套节点类型。
v0.10 在这个基础上新增一个小的控制流能力：可选 `else` 分支。

## 目标

- 支持 `if condition { ... } else { ... }`。
- 支持 `else` 写在右花括号同一行，也支持换到下一行。
- `else` 分支参与语义/类型检查。
- C 后端生成可读的 `if (...) { ... } else { ... }`。
- then/else 分支里的 `let` 变量不泄漏到外层，也不泄漏到另一侧分支。

## 非目标

- 不支持 `else if`。
- 不支持循环。
- 不支持函数参数、返回值或函数调用表达式。
- 不引入完整作用域系统，只维持当前块级符号表副本规则。

## 用户语法

```lai
fn main() {
    if true {
        print("yes")
    } else {
        print("no")
    }
}
```

也允许：

```lai
fn main() {
    if false {
        print("yes")
    }
    else {
        print("no")
    }
}
```

## AST

`IfStmt` 增加可选字段：

```python
else_statements: list[Stmt] | None = None
```

`None` 表示没有写 `else`；空列表表示写了空 `else` 块。

## Parser

- lexer 将 `else` 识别为 `ELSE`。
- 解析 `if` 的 then 块后，parser 尝试匹配可选 `else`。
- 如果 `}` 和 `else` 之间有换行，parser 使用短暂前瞻；只有真正看到 `ELSE` 才消费换行，否则恢复位置，让外层块继续按原规则处理语句换行。

## Checker

checker 对 then/else 分支分别复制当前符号表：

- then 分支内新增变量只在 then 分支内可见。
- else 分支内新增变量只在 else 分支内可见。
- 两个分支都不把变量写回外层。

## C Backend

生成形态：

```c
if (condition) {
    ...
} else {
    ...
}
```

后端的符号表规则与 checker 保持一致。

## 验收

- 单元测试覆盖 `if ... else ...` C 生成。
- 单元测试覆盖 `else` 写在下一行。
- 单元测试覆盖 then/else 分支变量不互通。
- AST 测试覆盖 `IfStmt.else_statements`。
- `python -m unittest discover -v` 通过。
- `python lai_compiler.py main.ly --run` 通过，并输出 `else works`。
