# LAI 项目知识库整理与有道云同步设计

日期：2026-07-28

## 目标

基于当前仓库源码和 `docs/ai` 项目记忆，整理一套面向开发者的 LAI（灵语）知识库，覆盖项目根目录、当前能力、编译架构、运行方式、未来版本规划和开发约定。

知识库同时保存在仓库与有道云笔记中。两端使用一致的主题划分和文件名，后续版本开发完成后可以按固定位置更新，不再依赖临时会话总结。

## 范围

本次工作包括：

- 总结项目根目录中的源码、测试、示例、文档和生成目录。
- 说明 LAI v0.35 的真实能力边界和 C / LLVM 后端差异。
- 整理 v0.36-v0.44 的滚动版本规划，以及待编号开发池和远期能力。
- 在仓库内创建可版本控制的知识库文档。
- 在有道云笔记中创建对应目录和 Markdown 笔记。
- 在根目录 `AGENTS.md` 增加知识库持续同步规则。

2026-07-28 用户确认后的执行范围进一步收窄：本轮不修改正在并行演进的
`README.md` 和 `docs/ai`，只创建当前 v0.35 知识库、完成有道云首次上传并补全
`AGENTS.md`。v0.36 完成后由新增规则驱动下一次知识库总结与上传。

本次工作不修改编译器源码、语言语法或运行时行为，也不把未来规划写成已实现能力。

## 信息来源与事实优先级

知识库内容按以下优先级取证：

1. 当前源码和测试。
2. `docs/ai/active-context.md` 与 `docs/ai/roadmap.md`。
3. `README.md`、`docs/ai/project-brief.md`、`docs/ai/architecture-map.md`、`docs/ai/module-index.md` 和 `docs/ai/conventions.md`。
4. 当前版本的设计与实施计划。
5. 历史会话日志、发布记录和远期愿景文档。

历史文档只作为演进记录。遇到 `.lai`、旧版本号、旧路线图或已变化的后端边界时，以当前代码和当前项目记忆为准，并在知识库中标明历史属性。

## 笔记职责

### `00_LAI 知识索引.md`

- 说明知识库范围、当前版本和最后核对日期。
- 提供其余五篇笔记的阅读顺序与职责。
- 明确源码、当前项目记忆、历史文档和远期愿景的事实优先级。
- 给出版本开发完成后的更新检查表。

### `01_项目根目录与模块地图.md`

- 按源码、测试、示例、文档、生成物、工具目录和早期实验文件总结根目录。
- 解释每个核心 Python 模块的职责。
- 区分手写源文件、跟踪文档、忽略的生成物和历史文件。

### `02_当前能力与运行方式.md`

- 记录 v0.35 已实现的类型、表达式、控制流、函数和比较能力。
- 记录默认 C 后端与实验性 LLVM 后端的能力差异。
- 给出单元测试、C 端到端示例和 LLVM 示例命令。
- 列出当前明确不支持的能力，避免路线图内容被误认为已发布功能。

### `03_架构与编译流程.md`

- 说明 `main.ly -> lexer -> parser -> AST -> checker -> backend -> clang -> exe` 数据流。
- 说明 lexer/parser、AST、checker、共享后端描述符、C 后端、LLVM 后端、clang 和 stdlib 边界。
- 记录新增语法时需要贯通的实现路径与常见一致性风险。

### `04_未来版本规划_v0.36-v0.44.md`

- 逐项记录 v0.36-v0.44 的目标、前置决策和明确非目标。
- 单独记录待编号开发池与暂不进入近期版本的能力。
- 明确版本号是滚动规划，不代表语法已确定或能力已实现。
- 保持“先完善独立语言，再评估 Unity 集成”的项目边界。

### `05_开发约定与文档入口.md`

- 汇总接手顺序、设计先行、测试、生成物和文档同步规则。
- 链接 `AGENTS.md`、`README.md`、`docs/ai`、版本设计与实施计划。
- 记录知识库的本地路径和有道云路径。
- 给出版本完成后的知识库更新与上传步骤。

## `AGENTS.md` 规则

在根目录 `AGENTS.md` 增加“知识库同步”约定：

- 每个用户可见版本或重要架构变更完成并验证后，检查本次变更涉及的最新开发文档。
- 将稳定、可复用且已由源码或测试验证的内容汇总到 `docs/knowledge-base/学习/开发/语言开发/灵语（LAI）/` 对应笔记。
- 同步上传到有道云 `学习/开发/语言开发/灵语（LAI）` 的同名笔记。
- 不上传构建产物、临时日志、密钥、个人信息或未经验证的推测。
- 规划项必须标明“未实现”，历史记录不得覆盖当前源码事实。
- 如果有道云未登录或网页不可用，明确记录未完成同步，不得假装已上传。

该规则只描述 LAI 项目的知识库维护，不把其他个人知识库约定扩展到仓库。

## 同步方式

本地 Markdown 文件是可审查、可版本控制的内容源。有道云笔记使用同名 Markdown 笔记作为阅读副本。

首次同步：

1. 创建有道云目录层级。
2. 按本设计中的文件名创建六篇 Markdown 笔记。
3. 将本地对应文件内容写入同名笔记。
4. 保存后重新进入目录，核对六篇笔记的标题和正文关键段落。

后续同步：

1. 完成语言版本开发、测试和项目文档更新。
2. 更新受影响的本地知识库笔记及索引中的版本和日期。
3. 将完整内容覆盖到有道云同名笔记。
4. 核对保存状态、标题、当前版本和路线图边界。

不通过网页抓取或复制仓库中的敏感文件；只上传本设计明确列出的知识库 Markdown 内容。

## 验证标准

本地验证：

- 六篇 Markdown 文件存在且文件名与设计一致。
- `rg` 一致性扫描中，当前版本统一为 v0.35，未来队列统一为 v0.36-v0.44。
- 所有未来能力明确标注为规划或未实现。
- 文档中的本地路径、模块名和命令在仓库中可解析。
- `git diff --check` 通过。

网页验证：

- `学习/开发` 下存在四个同级领域目录。
- `语言开发/灵语（LAI）` 下存在六篇同名 Markdown 笔记。
- `00_LAI 知识索引.md` 能看到 v0.35、六篇笔记职责和同步检查表。
- `04_未来版本规划_v0.36-v0.44.md` 能看到 v0.36-v0.44 且明确为未实现规划。
- 页面显示已保存；重新进入目录后标题和关键正文仍可读取。

由于本次只改文档，不重新运行编译器测试作为必要验收。知识库中的测试数量和发布结果若引用既有验证记录，必须注明它们来自 v0.35 发布记录，而不是本次重新执行。

- 设计文档、六篇知识库笔记和 `AGENTS.md` 已提交并推送。
