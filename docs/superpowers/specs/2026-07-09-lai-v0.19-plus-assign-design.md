# LAI v0.19 Plus Assignment Design

最后更新：2026-07-09

## 目标

v0.19 新增最小复合赋值语法：

```lai
count += 1
```

它等价于：

```lai
count = count + 1
```

这个版本只把已有的整数加法和重新赋值能力包装成更短写法，不引入新的算术体系。

## 设计取舍

选择先支持 `+=`，不同时支持 `-=`, `*=`, `/=` 或 `++`。

原因：

- 当前语言已经支持 `count = count + 1` 和整数加法，所以 `+=` 是已有能力的自然语法糖。
- 当前语言还不支持普通减法、乘法、除法、负数、括号表达式或完整运算符优先级；如果先支持 `-=`, 会出现 `count -= 1` 可用但 `count = count - 1` 不可用的割裂状态。
- `++` 只能表达加一，且容易引出前置/后置语义争议；v0.19 暂时不引入。
- 保持 v0 小步推进：先打通一个复合赋值 token、AST、checker 和 backend 链路。

## 范围

包括：

- 新增语句：

  ```lai
  count += expr
  ```

- `count` 必须是当前可见作用域中的已有变量或参数。
- `count` 必须是 `int`。
- `expr` 必须是 `int` 表达式。
- 生成 C 时输出为：

  ```c
  count = count + expr;
  ```

- `+=` 可用于 `main`、普通函数、`while`、`for` 和分支内部。

不包括：

- 不支持 `-=`, `*=`, `/=`。
- 不支持 `count++` 或 `++count`。
- 不支持普通减法表达式 `count - 1`。
- 不支持负数、括号表达式或完整运算符优先级。
- 不改变 `let` 或普通赋值 `name = expr` 的规则。

## 语法规则

```text
plus_assign_statement := name "+=" expr
```

示例：

```lai
fn main() {
    let count = 0
    count += 1
    print(count)
}
```

`+=` 是一个独立 token，优先于单独的 `+` 和 `=` 识别。

## 语义规则

- 左侧名称必须符合当前变量命名规则。
- 左侧名称必须已经在当前符号表中存在。
- 左侧类型必须是 `int`。
- 右侧表达式必须推导为 `int`。
- `+=` 不声明新变量，不改变变量类型。
- 循环和分支作用域规则沿用普通赋值：能修改已有变量，循环/分支内 `let` 的新变量不泄漏。

## 架构影响

### AST

新增：

- `PlusAssignStmt(name, value, line)`

### Lexer

新增 token：

- `PLUS_EQUAL`，对应源码 `+=`

`+=` 必须在单字符 token 分支之前识别。

### Parser

在 `_parse_statement(...)` 中，识别：

- `name = expr` -> `AssignStmt`
- `name += expr` -> `PlusAssignStmt`

`fn`、`main`、`let`、`print` 仍按当前兼容规则可作为名称使用；`if`、`else`、`return`、`while`、`for`、`from`、`to`、`break`、`continue`、`true`、`false` 不作为普通名称使用。

### Checker

新增 `PlusAssignStmt` 检查：

- 校验变量名。
- 校验变量已存在。
- 校验左侧变量类型是 `int`。
- 校验右侧表达式类型是 `int`。
- 报错信息带行号和实际类型。

### C Backend

生成：

```c
count = count + value;
```

保持输出简单可读，暂不生成 C 的 `+=`，避免把当前语义和未来后端优化绑死。

## 错误行为

需要测试覆盖：

- `count += 1` 生成 `count = count + 1;`。
- `count += add(1, 2)` 可用。
- 参数可以使用 `+=`。
- `while` / `for` 内可以使用 `+=`。
- 未知变量使用 `+=` 报错。
- `string` 或 `bool` 变量使用 `+=` 报错。
- 右侧不是 `int` 时报错。
- 当前仍不支持 `count -= 1`。
