# LAI v0.39 局部数组设计

日期：2026-09-05。状态：已按用户确认规则实现，完整测试与 C/LLVM 端到端验证通过。

## 已确认规则

- 数组必须显式声明 `int[]`、`string[]` 或 `bool[]`，例如 `let scores: int[] = [90, 95, 100]`。
- 支持有类型的空数组 `let empty: int[] = []`；数组长度由字面量元素个数确定，创建后固定。
- 数组字面量元素允许现有同类型表达式，严格匹配声明类型；按从左到右顺序各求值一次。元素内部沿用既有表达式求值规则，逻辑运算仍短路。
- 读取统一使用 `scores[index]`；索引类型严格为 `int`，从零开始，合法范围为 `0 <= index < length`，负数非法。
- 编译期可算出的越界索引在编译期拒绝；动态索引在访问内存前检查，失败向 `stderr` 输出行号、索引、长度并以 `EXIT_FAILURE` 退出。
- 数组可以声明在 main、用户函数、分支和循环的局部作用域内。读取结果是基础值，可用于现有表达式、打印、函数实参和返回。
- 本版不提供数组元素更新、数组整体赋值/复制、数组参数、数组返回值、数组比较或整体打印。
- v0.40 做元素更新、只读长度和遍历；v0.41 做多维数组；数组跨函数传递与整体复制登记到待编号池，先确定生命周期与复制语义。

## 源码示例

```lai
fn add(a: int, b: int) -> int {
    return a + b
}

fn show_arrays(index: int) {
    let scores: int[] = [90, add(90, 5), 100]
    let names: string[] = ["LAI", "LingYu"]
    let flags: bool[] = [true, scores[0] > 80]
    let empty: int[] = []
    print(scores[index])
    print(names[0])
    print(flags[1])
}

fn main() {
    show_arrays(1)
}
```

预期输出为 `95`、`LAI`、`1`（沿用现有 bool 打印规则）。示例 main 保持调用式组织。

## 与现有语法的结合

索引是后缀表达式，优先级高于一元运算；`-scores[0] * 2` 按 `(-(scores[0])) * 2` 解析，`scores[1 + 1]` 中索引允许现有整数表达式。括号包裹的数组名可以继续索引，如 `(scores)[0]`。

本版沿用既有单行表达式和逗号分隔规则，不增加尾逗号、跨行表达式、重复初始化、切片或方法调用。数组字面量只作为显式数组声明的直接初始化值；不做匿名数组或数组值的流转。

普通标量 `let` 保持现有推导语法。本版新增的变量类型标注只接受三种一维数组类型。函数签名中的数组类型应明确报不支持，不能隐式退化为指针。

## 编译器结构

- `lai_ast.py`：`LetStmt` 末尾新增默认 `None` 的 `type_name`，保留旧位置参数兼容；新增 `ArrayExpr(elements, line)`、`IndexExpr(target, index, line)`。
- `lai_compiler.py`：词法增加 `[`、`]`；类型读取识别后缀括号；数组字面量和后缀索引各自独立 parser helper；复合赋值中的索引与其他现有表达式一致。
- `lai_types.py`：不可变 `ArrayType(element_type, length)` 是局部符号信息，长度不写入源码类型；共享数组类型集合和只接受局部数组名（可带括号）的目标解析 helper。
- `lai_checker.py`：先检查每个初始化元素，再将数组写入当前作用域符号表；对数组整体使用报明确错误。索引检查返回数组元素类型并复用 `evaluate_static_i32` 做静态界限检查。
- `lai_c_backend.py`：使用内部 `CArrayBinding` 记录数组类型与 collision-free C 存储名。原始数组名不直接作为 C 存储名，避免遮蔽同名用户函数。
- `lai_stdlib.py`：提供返回安全索引的 helper；仅在程序含数组时加入数组 runtime 输出。
- `lai_llvm_backend.py`：仍保留受限子集，对有效数组声明明确报告 `LetStmt` 能力错误。

## 存储和生命周期

生成局部 C 数组，`int`/`bool` 使用现有 C `int` 表示，`string` 使用现有 `const char*`。长度为零时物理占位为 1，逻辑长度仍为 0；任何索引均越界。不使用 C 零长数组、VLA、堆分配或 GC。

生成顺序示意：

```c
int storage[3];
storage[0] = first();
storage[1] = second();
storage[2] = third();
printf("%d\n", storage[checked_index(index, 3, 8)]);
```

每个初始化值单独写入，保证初始化表达式从左到右各执行一次。编译期间不把当前数组提前放入符号表，因此自身初始化引用仍为未知变量。动态索引只作为 helper 实参求值一次；helper 返回前已检查完上下界。检查留在表达式位置，保持逻辑短路。

栈上存储跟随块作用域结束；数组不能逃逸。当前字符串内容来自既有静态字符串表示。本版不承诺超大局部数组或递归导致的栈耗尽恢复。

## 错误与测试

诊断统一保留 `line N`。静态和动态越界正文为 `array index out of bounds: index I, length N`。数组类型错误、无标注字面量、非整数索引、标量索引、数组整体使用和未支持写入分别给出直接原因。

验证覆盖三种基础类型、空数组、表达式初始化、作用域、索引优先级、所有现有标量使用位置、静态负数/上界/算术越界、动态负数/上界、索引单次求值、初始化顺序、短路跳过动态越界、名称冲突、LLVM 能力错误和旧 AST 构造兼容。
