# LAI v0.9 AST 节点拆分设计

日期：2026-07-08

## 目标

v0.9 将 LAI / 灵语的 AST 节点从 `lai_compiler.py` 拆到独立的 `lai_ast.py`。

本版本不新增用户语法，而是让 parser、checker 和 C backend 共享同一套 AST 类型。

## 范围

本版本支持：

- 新增 `lai_ast.py`。
- `lai_ast.py` 定义：
  - `Program`
  - `FunctionDef`
  - `LetStmt`、`PrintStmt`、`IfStmt`、`CallStmt`
  - `StringExpr`、`IntExpr`、`AddExpr`、`BoolExpr`、`CompareExpr`、`NameExpr`
- `lai_compiler.py` 的 parser 使用 `lai_ast.py` 中的节点创建 AST。
- `lai_compiler.py` 兼容导出这些 AST 节点。
- `lai_checker.py` 和 `lai_c_backend.py` 直接 import AST 节点，并使用 `isinstance(...)` 判断节点类型。

本版本不做：

- 不拆 lexer。
- 不拆 parser。
- 不新增 `else`、循环、函数参数或返回值。
- 不改变 `.ly` 用户源码语法。
- 不改变生成 C 的行为。

## 设计说明

`lai_ast.py` 只描述源码结构，不做语义检查，也不生成 C。

这样模块职责更清楚：

- `lai_compiler.py`：词法、语法、文件编译和 CLI。
- `lai_ast.py`：AST 节点定义。
- `lai_checker.py`：语义和类型检查。
- `lai_c_backend.py`：C 后端代码生成。

checker/backend 不再通过类名字符串判断节点，而是直接使用共享 AST 类：

```python
if isinstance(statement, LetStmt):
    ...
```

这会让后续新增语法节点时更容易阅读和维护。

## 兼容性

v0.9 不改变已有合法 `.ly` 程序的行为。

旧导入路径仍可用：

```python
from lai_compiler import Program, LetStmt, StringExpr
```

新代码也可以直接导入：

```python
from lai_ast import Program, LetStmt, StringExpr
```

## 测试

新增 `tests/test_lai_ast.py`，覆盖：

- `lai_compiler.py` 兼容导出 `lai_ast.py` 中的 AST 节点。
- parser 生成共享 AST 节点。
- checker/backend 直接 import 共享 AST 节点。

同时保留原有编译器测试、模块边界测试、标准库辅助测试和端到端验证。
