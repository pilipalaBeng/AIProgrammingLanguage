# LAI v0.17 Loop Return Flow Design

最后更新：2026-07-09

## 目标

v0.17 补齐一个很小的循环返回边界：返回值函数中的 `while` 循环体里可以写 `return expr`，但 `while` 本身仍不被视为“保证函数返回”的最终路径。

示例：

```lai
fn find(limit: int) -> int {
    let count = 0
    while count < limit {
        if count > 2 {
            return count
        }
        count = count + 1
    }
    return limit
}
```

## 范围

包括：

- 允许返回值函数的 `while` 循环体内出现 `return expr`。
- 循环内 `return expr` 必须符合函数声明的返回类型。
- 循环内直接所在块中的 `return` 仍必须是该块最后一条语句。
- 循环内嵌套的 `if / else if / else` 分支可以包含合法 `return`。
- `while` 作为返回值函数最后一条顶层语句时，仍不算保证返回。

不包括：

- 不支持通用早退：循环外的非最终 `if { return ... }` 仍保持拒绝。
- 不把 `while true { return ... }` 分析成保证返回。
- 不做不可达代码分析。
- 不改变 `main` 或无返回值函数中禁止 `return` 的规则。
- 不新增 `for`、`+=`、`++` 或其他语法。

## 语义规则

- 返回值函数中，如果 `while` 后面仍有顶层最终 `return` 或完整返回分支，则循环体里可以包含 `return`。
- 循环体中的 `return` 会被类型检查。
- 如果循环体同一块内 `return` 后仍有语句，编译器报错。
- 循环体里的分支返回不要求所有分支都返回，因为循环本身不保证执行，也不保证命中该分支。
- 最后一条顶层语句如果是 `while`，即使循环体里写了 `return`，函数仍会报 `function name must end with return`。

## 架构影响

### AST

不新增 AST 节点。继续使用现有：

- `WhileStmt`
- `IfStmt`
- `ReturnStmt`

### Parser

不新增语法。parser 已经能解析 `while` 和 `return`，无需修改。

### Checker

修改 `lai_checker.py`：

- 新增循环返回检查 helper。
- 在返回值函数的非最终顶层语句中，遇到 `WhileStmt` 时检查循环体内可能出现的 `return`。
- 在返回值函数的最终顶层语句中，遇到 `WhileStmt` 时也检查循环体内 `return`，但检查后仍报函数缺少最终返回。
- 循环体检查继续使用符号表副本和 `loop_depth + 1`。
- 循环内嵌套 `if` 分支使用同一套“允许局部 return，但不要求分支完整返回”的检查。

### C Backend

不需要新增能力。`ReturnStmt` 已经会生成：

```c
return value;
```

## 错误行为

新增或强化测试覆盖：

- 循环内 `return "bad"` 在 `-> int` 函数中报类型错误。
- 循环体同一块内 `return` 后继续写语句时报 `return must be the final statement in its block`。
- `while true { return 1 }` 作为函数唯一主体时仍报 `function value must end with return`。
- 无返回值函数中循环里的 `return` 仍报 `return is only allowed in functions with return type`。
