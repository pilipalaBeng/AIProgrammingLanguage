# LAI v0.25 Multiplication Expressions Design

## Goal

Add ordinary integer multiplication expressions to LAI v0 while keeping the
language small, testable, and consistent with the existing expression pipeline.

## Scope

v0.25 adds binary `*` expressions:

```lai
let count = 2 * 3
print(2 * 3)
return a * b
let value = 2 + 3 * 4
let grouped = (2 + 3) * 4
```

Multiplication is valid anywhere the current integer expressions are valid:

- `let` values
- `print(...)`
- `return`
- assignment values
- `+=` / `-=` right-hand values
- comparison operands
- function call arguments
- `while`, `if`, `for` start/end/step expressions when the surrounding rule
  already accepts an integer expression

## Precedence

v0.25 introduces the smallest useful precedence split:

- `*` binds tighter than `+` and `-`.
- `+` and `-` remain left-associative.
- `*` is left-associative for chained multiplication.
- Parentheses continue to override grouping.
- Comparison (`<`, `>`, `==`) remains outside arithmetic expressions.

Examples:

- `2 + 3 * 4` parses as `2 + (3 * 4)`.
- `(2 + 3) * 4` parses as `(2 + 3) * 4`.

This is not a full operator-precedence system. v0.25 still does not add unary
operators, division, modulo, logical operators, or assignment-expression
precedence.

## AST

Add `MultiplyExpr` in `lai_ast.py`:

```python
@dataclass(frozen=True)
class MultiplyExpr(Expr):
    factors: list["Expr"]
```

`MultiplyExpr` is shared by parser, checker, and C backend. `lai_compiler.py`
continues to re-export it for compatibility with existing tests and scripts.

## Parser

Add a `STAR` token for `*`.

Refactor expression parsing into:

```text
_parse_expr
  -> _parse_add_expr
       -> _parse_multiply_expr
            -> _parse_primary_expr
```

`_parse_add_expr` should parse `+` and `-` from multiplication-level operands.
`_parse_multiply_expr` should parse one or more primary expressions separated
by `*`.

## Type Checking

`MultiplyExpr` requires every factor to be `int` and returns `int`.

Suggested error:

```text
line N: multiplication operands must all be int, got string
```

## C Backend

Generate readable C by joining factor expressions with ` * `:

```c
int count = 2 * 3;
```

Existing `GroupExpr` output preserves parentheses, so `(2 + 3) * 4` stays
grouped in generated C.

## Tests

Add tests for:

- Tokenizing `*`.
- `let count = 2 * 3`.
- `print(2 * 3)`.
- `return a * b`.
- Function arguments using multiplication.
- `2 + 3 * 4` preserving multiplication before addition.
- `(2 + 3) * 4` preserving parenthesized grouping.
- `MultiplyExpr` AST construction and module re-exports.
- Incomplete multiplication, such as `1 *`.
- Non-int multiplication operands, such as `1 * "x"`.

## Non-Goals

v0.25 does not add:

- `*=`
- `/` or `/=`
- `%`
- `count++`
- negative integers or unary minus
- string repetition
- full operator precedence
- LLVM IR changes
