# LAI v0.6 基础类型检查设计

日期：2026-07-08

## 目标

v0.6 为 LAI / 灵语加入显式的语义和基础类型检查阶段。

当前编译链路从：

```text
source -> lexer -> parser -> AST -> C codegen -> clang
```

扩展为：

```text
source -> lexer -> parser -> AST -> semantic/type checker -> C codegen -> clang
```

## 范围

本版本支持：

- 新增 `check_program(program)` 作为公开 checker 入口。
- 在生成 C 前检查每个函数内的局部变量符号表。
- 检查未知变量、重复变量、未知函数调用和重复函数定义。
- 跟踪三种基础表达式类型：`string`、`int`、`bool`。
- `if` 条件必须是 `bool`。
- 整数加法表达式的所有操作数必须是 `int`。
- 比较表达式当前要求两侧都是 `int`，结果为 `bool`。
- 类型错误信息包含行号和实际类型，例如 `got string and int`。

本版本不做：

- 不新增表面语法。
- 不加入类型注解。
- 不加入完整类型推导或类型统一算法。
- 不支持字符串相加。
- 不支持布尔比较、字符串比较或混合类型比较。
- 不支持函数参数、返回值或函数调用表达式。

## 设计说明

checker 仍保留在 `lai_compiler.py` 单文件内，但独立成 `check_program(program)` 和内部辅助函数。
这样既不增加文件拆分成本，也为后续拆出 `checker.py` 留出清晰边界。

`generate_c(program)` 会先调用 `check_program(program)`。只有检查通过后，才继续生成 C 代码。
这样可以避免依赖 C 编译器暴露 LAI 语义错误，也让单元测试可以直接断言 LAI 层错误信息。

## 兼容性

v0.6 不改变已有合法程序的输出结果。

少数过去可能在 C 生成阶段或更晚才失败的错误，现在会在 LAI checker 阶段提前失败，并给出更明确的错误信息。

## 测试

新增测试覆盖：

- `check_program(program)` 接受合法程序。
- 字符串和整数比较会报类型错误。
- `if 1 { ... }` 会报非布尔条件错误。

同时保留原有词法、解析、C 生成、函数调用和端到端测试。
