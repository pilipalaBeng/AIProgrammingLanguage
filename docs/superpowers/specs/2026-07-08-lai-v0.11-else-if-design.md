# LAI v0.11 Else If 语法设计

最后更新：2026-07-08

## 背景

v0.10 已经支持可选 `else`，并且 `IfStmt.else_statements` 可以保存 else 分支语句。
v0.11 在此基础上加入 `else if` 链式分支，让用户不用手写嵌套 `if`。

## 目标

- 支持 `else if condition { ... }`。
- 支持多段 `else if` 链。
- 支持链尾继续写普通 `else`。
- 复用现有 `IfStmt`，把 `else if` 表示为 else 分支里的嵌套 `IfStmt`。
- 保持现有 checker/backend 作用域规则：每个分支使用独立符号表副本。

## 非目标

- 不新增单词关键字 `elseif`。
- 不支持循环。
- 不支持函数参数、返回值或函数调用表达式。
- 不改变当前表达式优先级。

## 用户语法

```lai
fn main() {
    if score > 90 {
        print("A")
    } else if score > 80 {
        print("B")
    } else {
        print("C")
    }
}
```

多段链：

```lai
fn main() {
    if score > 90 {
        print("A")
    } else if score > 80 {
        print("B")
    } else if score > 70 {
        print("C")
    } else {
        print("D")
    }
}
```

## AST 表示

不新增 `ElseIfStmt`。

`else if` 等价于：

```lai
if a {
    print("A")
} else {
    if b {
        print("B")
    } else {
        print("C")
    }
}
```

因此 AST 表示为：

- 外层 `IfStmt.else_statements`
- 包含一个内层 `IfStmt`
- 内层 `IfStmt.else_statements` 再保存后续链或最终 else

## Parser

parser 在解析 `else` 后：

- 如果下一个 token 是 `IF`，解析一个嵌套 `IfStmt`，并把它作为 `else_statements` 的唯一语句。
- 否则保持 v0.10 行为，要求后面是 `{ ... }` 普通 else 块。

## Checker 和 C Backend

checker/backend 不需要新增节点分支。
因为 `else if` 已经被 parser 表示成嵌套 `IfStmt`，现有 `IfStmt` 逻辑会自然检查和生成：

```c
if (a) {
    ...
} else {
    if (b) {
        ...
    } else {
        ...
    }
}
```

## 验收

- 单元测试覆盖 `else if` 生成嵌套 C `if`。
- 单元测试覆盖多段 `else if` 链。
- 单元测试覆盖 `else if` 条件的类型检查。
- AST 测试覆盖 `else if` 被解析为嵌套 `IfStmt`。
- `python -m unittest discover -v` 通过。
- `python lai_compiler.py main.ly --run` 通过，并输出 `else if works`。
