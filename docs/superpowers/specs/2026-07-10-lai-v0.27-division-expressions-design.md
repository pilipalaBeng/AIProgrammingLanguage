# LAI v0.27 Division Expressions Design

## Goal

Add ordinary integer division expressions to LAI v0 while keeping arithmetic
semantics explicit in LAI instead of delegating language rules to C or LLVM.

## Scope

v0.27 adds binary `/` expressions:

```lai
let count = 8 / 2
print(8 / 2)
return a / b
let value = 8 + 6 / 2
let grouped = (6 + 4) / 2
```

Division is valid anywhere the current integer expressions are valid:

- `let` values
- `print(...)`
- `return`
- assignment values
- `+=` / `-=` / `*=` right-hand values
- comparison operands
- function call arguments
- `while`, `if`, `for` start/end/step expressions when the surrounding rule
  already accepts an integer expression

## Semantics

`int / int` returns `int` and follows C integer division for now. For example:

```lai
print(5 / 2)
```

generates C integer division, so the result is `2`.

The compiler owns this LAI rule. The C backend and future LLVM backend are code
generation targets, not language-design authorities.

## Precedence

v0.27 keeps the existing minimal arithmetic precedence split:

- `*` and `/` share the same precedence.
- `*` and `/` bind tighter than `+` and `-`.
- `+` and `-` remain left-associative.
- `/` is left-associative for chained division and mixed multiplication.
- Parentheses continue to override grouping.
- Comparison (`<`, `>`, `==`) remains outside arithmetic expressions.

Examples:

- `8 + 6 / 2` parses as `8 + (6 / 2)`.
- `8 / 2 * 3` behaves as `(8 / 2) * 3`.
- `(6 + 4) / 2` preserves the grouped numerator.

This is still not a full operator-precedence system. v0.27 does not add unary
operators, modulo, logical operators, floating-point numbers, or assignment
expression precedence.

## AST

Add `DivideExpr` in `lai_ast.py`:

```python
@dataclass(frozen=True)
class DivideExpr(Expr):
    left: Expr
    right: Expr
```

`DivideExpr` is shared by parser, checker, and C backend. `lai_compiler.py`
continues to re-export it for compatibility with existing tests and scripts.

## Lexer And Parser

Keep `//` as line comments. Tokenize single `/` as `SLASH` only after the line
comment check.

Update the current multiplication parser layer to parse both `*` and `/`.
`*` can keep using `MultiplyExpr(factors)` for chained multiplication, while
`/` builds `DivideExpr(left, right)` and preserves left associativity.

## Type Checking

`DivideExpr` requires both operands to be `int` and returns `int`.

Suggested errors:

```text
line N: division operands must both be int, got string and int
line N: division by zero
```

The `division by zero` check only covers obvious static zero denominators such
as `8 / 0` and `8 / (0)`. v0.27 does not add runtime checks for dynamic values.

## C Backend

Generate readable C:

```c
int count = 8 / 2;
```

Existing `GroupExpr` output preserves parentheses, so `(6 + 4) / 2` stays
grouped in generated C.

## Tests

Add tests for:

- Tokenizing `/` without breaking `//` comments.
- `let count = 8 / 2`.
- `print(8 / 2)`.
- `return a / b`.
- Function arguments using division.
- `8 + 6 / 2` preserving division before addition.
- `8 / 2 * 3` preserving same-level arithmetic output.
- `(6 + 4) / 2` preserving parenthesized grouping.
- `DivideExpr` AST construction and module re-exports.
- Incomplete division, such as `8 /`.
- Non-`int` division operands, such as `8 / "x"`.
- Static division by zero, such as `8 / 0` and `8 / (0)`.

## Non-Goals

v0.27 does not add:

- `/=`
- `%` or `%=`
- floating-point numbers
- negative integers or unary minus
- dynamic runtime division-by-zero checks
- `count++`
- full operator precedence
- LLVM IR changes
