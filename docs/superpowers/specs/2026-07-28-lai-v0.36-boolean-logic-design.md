# LAI v0.36 布尔逻辑表达式设计

日期：2026-07-28
状态：设计已确认，待实施。

## 1. 背景

LAI v0.35 已有 `bool` 字面量、布尔变量、返回 `bool` 的函数和六种基础比较，
但还不能直接组合多个布尔条件，也不能对布尔值取反。

v0.36 补齐逻辑与、逻辑或和逻辑非，并明确短路求值、优先级和严格类型规则。
本版继续保持完整 C 后端稳定，不扩大实验性 LLVM 后端的布尔和控制流范围。

## 2. 已确认语法

设计阶段比较过三种形式：

1. 单词关键字：`and`、`or`、`not`。
2. C/Rust 风格符号：`&&`、`||`、`!`。
3. 同时支持单词和符号别名。

采用方案 1：

```lai
if ready and count > 0 {
    print("ready")
}

if not finished or retry {
    print("continue")
}
```

单词形式更接近自然语言，生成、审查和解释代码时更自说明，也符合 LAI
减少语法噪音、面向初学者和 AI 协作的定位。源码形式不会影响性能；C 后端仍生成
标准的 `!`、`&&`、`||`。

本版不同时支持符号别名，避免形成两套风格、重复测试矩阵和格式化选择。

## 3. 词法与兼容性

新增三个关键字 token：

```text
and -> AND
or  -> OR
not -> NOT
```

`and`、`or`、`not` 成为保留字，不能再作为变量名、参数名或函数名。v0.35
曾把它们当作普通 `IDENT`；这是新增语法所需的源码兼容性变化。

符号形式保持不支持：

```text
&&
||
!
```

它们继续由 lexer 报 `unexpected character`。现有 `!=` 必须继续通过双字符最长匹配
识别为 `BANG_EQUAL`，不能受单独 `!` 不支持的边界影响。单独的 `&`、`|` 也不代表
逻辑或按位运算。

## 4. AST

新增两个不可变节点：

```python
@dataclass(frozen=True)
class LogicalNotExpr(Expr):
    operand: Expr


@dataclass(frozen=True)
class LogicalExpr(Expr):
    left: Expr
    operator: str
    right: Expr
```

`LogicalExpr.operator` 只允许 `and` 或 `or`。使用独立节点而不复用整数 `UnaryExpr`
或 `CompareExpr`，让 parser、checker 和 backend 的整数、比较、逻辑职责保持清楚。

连续 `and` / `or` 按左结合构造二元节点。左结合不会改变纯布尔结果，并能在 AST
和生成 C 中明确保留从左到右的短路顺序。

## 5. 解析与优先级

表达式语法更新为：

```text
expr          := or_expr
or_expr       := and_expr ("or" and_expr)*
and_expr      := not_expr ("and" not_expr)*
not_expr      := "not" not_expr | comparison_expr
comparison_expr := add_expr (comparison_op add_expr)?
comparison_op := "<" | "<=" | ">" | ">=" | "==" | "!="
add_expr      := multiply_expr (("+" | "-") multiply_expr)*
multiply_expr := unary_expr (("*" | "/" | "%") unary_expr)*
unary_expr    := ("+" | "-") unary_expr | primary_expr
primary_expr  := literal | name | call | "(" expr ")"
```

优先级从高到低为：

1. 基础表达式和括号。
2. 整数一元 `+`、`-`。
3. `*`、`/`、`%`。
4. 二元 `+`、`-`。
5. `<`、`<=`、`>`、`>=`、`==`、`!=`。
6. `not`。
7. `and`。
8. `or`。

因此：

```lai
not count < 3
```

等价于：

```lai
not (count < 3)
```

而：

```lai
ready or active and allowed
```

等价于：

```lai
ready or (active and allowed)
```

`not` 右结合，因此 `not not ready` 合法。因为 `not` 低于比较，逻辑非若要直接作为
比较右侧，必须显式分组，例如 `ready == (not finished)`。

v0.35 的未分组比较链错误保持不变。`1 < 2 and 2 < 3` 是两个独立比较的逻辑与，
合法；`1 < 2 < 3` 仍报 `comparison chains are not supported`。

## 6. 类型规则

LAI 继续采用严格布尔规则，不引入 truthiness：

| expression | operand requirements | result |
|---|---|---|
| `not value` | `value` 必须是 `bool` | `bool` |
| `left and right` | 两侧都必须是 `bool` | `bool` |
| `left or right` | 两侧都必须是 `bool` | `bool` |

以下源码均非法：

```lai
not 1
1 and true
false or "text"
```

错误信息采用：

```text
line N: logical not operand must be bool, got TYPE
line N: logical and operands must both be bool, got LEFT and RIGHT
line N: logical or operands must both be bool, got LEFT and RIGHT
```

checker 会静态检查逻辑表达式的所有 operand，即使右侧在某次运行中会被短路。
手工构造的 `LogicalExpr` 若使用未知 operator，优先报：

```text
line N: unsupported logical operator: OPERATOR
```

## 7. 短路求值与 C 后端

`and` 和 `or` 必须短路：

- `left and right`：先计算 `left`；若为 `false`，不计算 `right`。
- `left or right`：先计算 `left`；若为 `true`，不计算 `right`。

C 后端直接映射到标准 C 逻辑运算，并为每层 AST 加括号：

```lai
not ready
ready and check()
ready or check()
```

```c
(!(ready))
((ready) && (check()))
((ready) || (check()))
```

C 的 `&&` 和 `||` 保证先计算左侧并按上述规则跳过右侧。后端只能递归生成右侧 C
文本，不能在逻辑表达式外提前求值到临时变量，否则会破坏短路语义。

`C_BACKEND.emit()` 可以被直接调用，因此 C lowering 不能只依赖入口处已经运行
checker。`_expr_to_c_value()` 必须再次验证 `LogicalNotExpr` operand 是 `bool`，
`LogicalExpr` operator 是 `and` / `or` 且两侧都是 `bool`，并复用第 6 节的错误措辞。
未知 operator 必须在递归处理 operand 前报错，不能写入生成的 C。

逻辑结果继续使用当前 C `int` 布尔表示，值为 `0` 或 `1`。字符串比较等已有表达式
可以作为逻辑 operand，例如：

```lai
name == "JD" and ready
```

生成的核心 C 表达式为：

```c
((strcmp(name, "JD") == 0) && (ready))
```

## 8. 表达式位置

逻辑表达式应沿用现有通用表达式入口，可出现在：

- `let` 初始化和普通赋值。
- `print`。
- `if` / `else if` / `while` 条件。
- 函数实参。
- 返回值。
- 括号分组和其他逻辑表达式内部。

现有 `bool` 参数、返回类型和变量赋值检查无需改变，只需让新 AST 正确推断为
`bool`。

## 9. LLVM 边界

实验性 LLVM 后端仍只支持顶层整数 `print` 子集，连 `BoolExpr`、`CompareExpr`
和控制流都未支持。合法逻辑表达式通过 checker 后，LLVM emitter 应稳定报告：

```text
line N: LLVM backend does not support LogicalNotExpr yet
line N: LLVM backend does not support LogicalExpr yet
```

v0.36 不新增布尔值、`icmp`、条件分支、基本块或 `phi` lowering。LLVM 的真实短路
需要控制流设计，应与后续变量、比较和控制流追平工作一起处理。

## 10. 明确不做

v0.36 不支持：

- `&&`、`||`、`!` 别名。
- 整数或字符串 truthiness。
- 按位 `&`、`|`、`^`、`~`。
- 逻辑复合赋值。
- 布尔常量折叠优化。
- 比较链。
- LLVM 布尔逻辑 lowering。

## 11. 验收标准

- lexer 正确识别 `and`、`or`、`not`，并将它们作为保留字。
- parser 生成不可变的 `LogicalNotExpr` 和 `LogicalExpr`。
- 优先级、左右结合、括号和比较链边界符合本设计。
- checker 只接受 `bool` operand，并防御未知逻辑 operator。
- C 后端生成带括号的 `!`、`&&`、`||`，且真实运行验证短路。
- 直接调用 `C_BACKEND.emit()` 时，非法逻辑 AST 仍会被 C lowering 防御性拒绝。
- 逻辑表达式覆盖所有现有通用表达式位置。
- LLVM 对两个新 AST 节点继续报明确能力错误。
- 新增 C 可运行示例，包含比较组合、优先级、括号、双重 `not` 和短路行为。
- 完整单元测试、既有 C/LLVM 示例和默认 `main.ly` 全部通过。
- 当前能力文档、路线图和版本说明保持一致。
