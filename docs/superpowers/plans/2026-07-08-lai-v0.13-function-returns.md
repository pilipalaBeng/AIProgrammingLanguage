# LAI v0.13 Function Returns Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add explicit function return types, `return expr`, and function-call expressions.

**Architecture:** Extend the shared AST with `ReturnStmt`, `CallExpr`, and `FunctionDef.return_type`. Parser reads `-> type`, return statements, call expressions, and name/call-based integer addition. Checker owns return validation and function call expression types. C backend emits typed `static` functions and converts call expressions inside existing expression codegen.

**Tech Stack:** Python 3.12+, standard-library `unittest`, LAI `.ly` sources, C backend compiled by `clang`.

## Global Constraints

- Return types are limited to `string`, `int`, and `bool`.
- `fn main()` must remain parameterless and must not declare a return type.
- Functions without `-> type` remain no-return-value functions.
- Returning functions must end with a top-level `return expr`.
- `return` inside `if` branches is not part of v0.13.
- Do not add recursion-specific behavior, overloads, default arguments, named arguments, varargs, or a full operator precedence system.
- Keep `compile_source(source: str) -> str` as the primary test entry.
