# LAI v0.22 Parenthesized Expressions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add real parenthesized expressions that preserve grouping through parser, AST, checker, and C backend.

**Architecture:** Add `GroupExpr` as a lightweight AST wrapper around an inner expression. Parse `("(" expr ")")` at primary-expression level, infer the wrapped expression type in the checker, and emit parenthesized C in the backend.

**Tech Stack:** Python 3.12+, `unittest`, existing LAI lexer/parser/checker/C backend, local `clang`.

## Global Constraints

- Parentheses must affect expression grouping.
- Do not add `-`, `*`, `/`, negative numbers, or full operator precedence.
- Do not change existing `+` or comparison behavior.
- Do not add new Python dependencies.
- Write failing tests before production changes.
- Keep `to` exclusive and `through` inclusive.
