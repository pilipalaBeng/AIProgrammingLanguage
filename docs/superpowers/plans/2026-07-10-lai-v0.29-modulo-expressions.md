# LAI v0.29 Modulo Expressions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add ordinary integer modulo expressions.

**Architecture:** Add `ModuloExpr` beside existing arithmetic AST nodes.
Tokenize `%` as `PERCENT`, parse it in the same precedence layer as `*` and
`/`, validate both operands as `int`, reject obvious static zero right-hand
operands, and emit readable C using `%`.

**Tech Stack:** Python 3.12+, `unittest`, existing LAI lexer/parser/checker/C
backend, local `clang`.

## Global Constraints

- Add `%` modulo expressions only.
- `%` shares precedence with `*` and `/`, and binds tighter than `+` / `-`.
- `int % int` returns `int` using C integer remainder semantics for now.
- Reject obvious static zero right-hand operands such as `7 % 0` and `7 % (0)`.
- Do not add `%=`, `count++`, floating-point numbers, negative integers, unary
  minus, dynamic runtime modulo-by-zero checks, logical operators, assignment
  expressions, or full operator precedence.
- Do not change existing `+`, `-`, `*`, `/`, comparison, `+=`, `-=`, `*=`,
  `/=`, `for`, `while`, or return behavior except where modulo becomes a valid
  integer subexpression.
- Do not add new Python dependencies.
- Write failing tests before production changes.
- Keep generated C simple and readable.

if isinstance(expr, ModuloExpr):
    left_kind = _infer_expr_type(expr.left, symbols, line, function_signatures)
    right_kind = _infer_expr_type(expr.right, symbols, line, function_signatures)
    if left_kind != "int" or right_kind != "int":

    return "int"
