# LAI v0.17 Loop Return Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Allow typed `return` statements inside `while` loops in returning functions without treating `while` as a guaranteed final return path.

**Architecture:** Keep AST, parser, and C backend unchanged. Extend `lai_checker.py` with loop-return validation helpers used only when checking returning functions. The checker validates return type and block-finality inside loops, but still requires a final top-level return or full branch return after the loop.

**Tech Stack:** Python 3.12+, `unittest`, existing LAI lexer/parser/checker/C backend, local `clang`.

## Global Constraints

- Keep `fn main()` parameterless and returnless.
- Do not add `for`, `count++`, `+=`, unreachable-code analysis, or `while true` guaranteed-return analysis.
- Do not add new Python dependencies.
- Write failing tests before production changes.
- Preserve current `.ly -> C -> clang -> exe` pipeline.

```python
def test_returning_function_allows_return_inside_while_before_final_return(self):
    c_code = compile_source("""fn find(limit: int) -> int {
    let count = 0
    while count < limit {
        if count > 2 {
            return count
        }
        count = count + 1
    }
    return limit
}

fn main() {
    print(find(5))
}""")

    self.assertIn("while (count < limit) {", c_code)
    self.assertIn("return count;", c_code)
    self.assertIn("return limit;", c_code)
```
