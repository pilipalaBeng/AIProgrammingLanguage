# LAI v0.11 Else If Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `else if` chains as syntax sugar over the existing `IfStmt` AST.

**Architecture:** The lexer already recognizes `else` and `if` separately. The parser will parse `else if` by placing a nested `IfStmt` inside `else_statements`, so checker and C backend can reuse their current `IfStmt` logic.

**Tech Stack:** Python 3.12+, standard-library `unittest`, LAI `.ly` sources, C backend compiled by `clang`.

## Global Constraints

- Do not add the single-word keyword `elseif`.
- Do not add loops, function parameters, return values, or new expression precedence.
- Keep `compile_source(source: str) -> str` as the primary test entry.
- Update docs whenever project behavior changes.

- [ ] **Step 1: Write failing tests**

Add tests that assert:

```python
c_code = compile_source("""fn main() {
    let score = 85
    if score > 90 {
        print("A")
    } else if score > 80 {
        print("B")
    } else {
        print("C")
    }
}""")
self.assertIn("if (score > 90) {", c_code)
self.assertIn("if (score > 80) {", c_code)
self.assertIn('printf("B\\n");', c_code)
```


Expected: fail with `expected LBRACE` after `else`, because v0.10 expects `else {`.
