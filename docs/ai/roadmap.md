# LAI 版本路线图

最后更新：2026-07-06

## 目的

本文记录 LAI 当前原型阶段的版本规划，帮助后续开发保持小步推进。这里的版本号代表项目阶段目标，不代表已经发布的稳定语言规范。

每个版本都应保持：

- 范围小，可测试，可运行。
- 新语法先写测试，再改编译器。
- 优先保持 `lexer -> parser -> AST -> C codegen -> clang` 管线稳定。
- 不把远期愿景文档里的能力提前描述为已实现。

## 当前版本

### v0.3：布尔值、比较表达式和 `if`

状态：已完成。

目标：

- 支持布尔值：`true`、`false`。
- 支持基础比较表达式：`1 < 2`、`count == 3`、`3 > 2`。
- 支持最小 `if` 语句。
- 暂不支持 `else`、循环、括号表达式或完整运算符优先级。

当前支持：

- `fn main() { ... }`
- `// comment`
- `let name = "text"`
- `let count = 123`
- `let count = 1 + 2`
- `let ready = true`
- `let ok = count == 3`
- `print("text")`
- `print(123)`
- `print(1 + 2)`
- `print(true)`
- `print(1 < 2)`
- `print(name)`
- `if ready { ... }`
- `if 1 < 2 { ... }`

## 已完成

### v0.2：注释和简单表达式

状态：已完成。

目标：

- 支持 `// comment` 单行注释。
- 支持简单整数加法表达式，例如 `print(1 + 2)`。
- 支持 `let count = 1 + 2`。
- 保持表达式范围极小，暂不加入优先级复杂的多运算符体系。

### v0.1：结构化编译器管线

状态：已完成。

目标：

- 建立 `source -> lexer -> parser -> AST -> C codegen -> clang` 管线。
- 保持 `python lai_compiler.py main.lai --run` 可用。
- 支持最小语法闭环。

## 近期规划

### v0.4：用户自定义函数

建议目标：

- 支持定义简单函数。
- 支持从 `main` 调用用户函数。
- 暂不做复杂重载、泛型、闭包或模块系统。

意义：

- 让程序可以拆分逻辑。
- 让语言开始具备组织中型示例的能力。

### v0.5：基础类型检查和错误提示

建议目标：

- 引入更明确的基础类型检查。
- 改善错误信息中的行列号和上下文。
- 明确变量、表达式、打印参数的类型规则。

意义：

- 降低后续语法扩展带来的不确定性。
- 让错误行为更适合测试和文档化。

### v0.6：文件拆分和小型标准库雏形

建议目标：

- 视代码规模拆分 `lai_compiler.py`。
- 探索最小标准库边界。
- 保持 C 后端稳定。

意义：

- 避免单文件编译器过大。
- 为后续更多语言能力提供更清楚的模块边界。

## 远期探索

### v0.7+：LLVM 后端探索

建议目标：

- 在 C 后端稳定后，再探索 LLVM IR。
- 不要同时大改语法和后端。
- 先选一个极小程序验证 LLVM 生成链路。

意义：

- 为长期高性能方向做准备。
- 保持每一步都有可运行闭环。

## 暂不规划进近期版本的能力

- GC。
- JIT。
- 并发调度。
- 包管理。
- 模块系统。
- 泛型。
- 宏系统。
- AI 自动优化能力。

这些属于远期方向，当前不应压进 v0.x 早期闭环。
