# 未来数据结构命名草案

最后更新：2026-07-30

## 目的

本文记录 LAI / 灵语未来数据结构的命名方向，避免后续设计数组、字典等能力时反复摇摆。

这些内容是未来设计方向，不代表当前 v0.38 编译器已经支持。当前已实现的用户可见类型仍只有
`string`、`int` 和 `bool`。

当前 v0.38 已完成通用函数早退、首条不可达诊断、精确所有路径返回和最小静态 `while true` 证明；C lowering 未改变，LLVM 仍不支持用户函数或控制流。下一版 v0.39 是数组核心，多维数组已插入 v0.41，剩余队列为 v0.39-v0.45，共 7 个版本；这些事实不改变本文的数据结构仍属未来设计。

## 命名原则

- 优先照顾 C# 程序员的阅读习惯。
- 保持语法短小，不引入过重的泛型外观。
- 避免同一个词在类型名和常用操作中产生不必要混淆。
- 新增数据结构前必须先写设计、计划和测试。

## 已确认的命名方向

### 数组：`int[]`

未来数组优先采用 C# 风格的后缀写法：

```lai
let scores: int[] = [90, 95, 100]
```

原因：

- 对 C# 程序员更直观。
- `int[]` 一眼能看出“元素是 `int` 的数组”。
- 远期文档中曾出现过 `[]int` 示例，但该示例不作为正式决定。

已确认的语义方向：

- `int[]` 是固定长度数组：创建后长度不变，不支持 `append`、`remove` 或自动扩容。
- 数组元素可变，但 v0.39 只实现创建和读取；索引更新排入 v0.40。
- 固定长度不等于完全不可变；v0.40 的元素更新只替换已有位置，不改变数组长度。
- 动态长度容器不复用数组语义，未来独立设计为 `list<T>`。

v0.39 已确认使用显式数组声明，并支持当前三种基础元素类型：

```lai
let scores: int[] = [90, 95, 100]
let names: string[] = ["LAI", "LingYu"]
let flags: bool[] = [true, false]
let empty: int[] = []
```

数组字面量中的所有元素必须与声明类型一致，不允许混合元素类型。`int[][]` 等多维数组不属于 v0.39，已单独插入 v0.41；矩形数组、交错数组和最终类型形式留到该版本设计时确认。

### 字典：`dict`

未来键值表优先命名为 `dict`：

```lai
let ages: dict<string, int> = {
    "Alice": 18
}
```

原因：

- `dict` 对有 C# / Python 背景的读者都比较容易理解。
- 避免类型名 `map` 和集合操作 `.map(...)` 撞名。
- 比 `Dictionary` 更短，更符合 LAI 极简语法方向。

暂定示例：

```lai
dict<string, int>      // 字符串到整数
dict<string, bool>     // 字符串到布尔值
dict<int, string>      // 整数到字符串
```

## 尚未确认的方向

以下数据结构还没有完整设计：

- 动态列表已确定不复用数组，类型方向为 `list<T>`；其 API、内存语义和版本号仍未确认。
- 集合是否命名为 `set`。
- 结构化数据使用 `struct`、`record` 还是其他关键字。
- 张量和批量数据是否使用专门类型，还是先通过数组表达。
- 字典类型参数使用 `dict<string, int>` 还是其他分隔形式。

## 与当前实现的关系

当前编译器不支持：

- 数组字面量。
- 数组索引。
- 字典字面量。
- 字典读取或写入。
- 类型标注。
- 泛型或类型参数。

在这些能力真正进入实现前，应先新增对应版本设计文档和测试计划。

数组核心现已排入 v0.39，数组实用操作与遍历排入 v0.40，多维数组插入 v0.41。v0.39 已确认数组声明必须显式写出 `int[]`、`string[]` 或 `bool[]`；该能力只覆盖数组所需的最小变量类型标注，不代表通用变量类型标注已经实现。

版本任务边界已经确认：

- v0.39：显式类型的固定长度数组创建、索引读取、元素类型检查、索引类型/越界规则和最小 C 表示。
- v0.40：元素索引更新、只读长度和最小遍历；不加入改变长度的操作。
- v0.41：多维数组最小闭环；类型形式、矩形/交错语义和内存模型必须先单独设计确认。
- 待编号开发池：独立动态 `list<T>`，后续再设计扩容、`append`、`remove` 和遍历。

这不等于通用变量类型标注或完整类型推导已经排入 v0.39。字典实现已经登记到待编号
开发池，具体版本要在数组、字符串与基础类型规则稳定后确认。
