# 未来数据结构命名草案

最后更新：2026-07-28

## 目的

本文记录 LAI / 灵语未来数据结构的命名方向，避免后续设计数组、字典等能力时反复摇摆。

这些内容是未来设计方向，不代表当前 v0.37 编译器已经支持。当前已实现的用户可见类型仍只有
`string`、`int` 和 `bool`。

当前 v0.37 已完成单一 checked i32 模式：纯静态零除和中间溢出由编译期诊断，动态 C 算术由运行时 helper 检查，错误写入 `stderr` 后以 `EXIT_FAILURE` 终止。`for` 的三个值只求值一次，动态正 step 和 i32 上界范围完成均受运行时保护；内部前缀按每次生成避开用户名称。LLVM 只保留纯静态顶层整数 `print` 子集，动态值和控制流仍不支持。示例是 `examples/runtime_integer_safety.ly`。下一版 v0.38 是通用函数早退，剩余队列为 v0.38-v0.44，共 7 个版本；这些事实不改变本文的数据结构仍属未来设计。

## 命名原则

- 优先照顾 C# 程序员的阅读习惯。
- 保持语法短小，不引入过重的泛型外观。
- 避免同一个词在类型名和常用操作中产生不必要混淆。
- 新增数据结构前必须先写设计、计划和测试。

## 已确认的命名方向

### 数组：`int[]`

未来数组优先采用 C# 风格的后缀写法：

```lai
let scores: int[] = [90, 95, 100]
```

原因：

- 对 C# 程序员更直观。
- `int[]` 一眼能看出“元素是 `int` 的数组”。
- 远期文档中曾出现过 `[]int` 示例，但该示例不作为正式决定。

暂定示例：

```lai
int[]        // 整数数组
string[]     // 字符串数组
bool[]       // 布尔数组
int[][]      // 二维整数数组
```

### 字典：`dict`

未来键值表优先命名为 `dict`：

```lai
let ages: dict<string, int> = {
    "Alice": 18
}
```

原因：

- `dict` 对有 C# / Python 背景的读者都比较容易理解。
- 避免类型名 `map` 和集合操作 `.map(...)` 撞名。
- 比 `Dictionary` 更短，更符合 LAI 极简语法方向。

暂定示例：

```lai
dict<string, int>      // 字符串到整数
dict<string, bool>     // 字符串到布尔值
dict<int, string>      // 整数到字符串
```

## 尚未确认的方向

以下数据结构还没有正式命名：

- 动态列表是否直接复用数组，还是单独命名为 `list`。
- 集合是否命名为 `set`。
- 结构化数据使用 `struct`、`record` 还是其他关键字。
- 张量和批量数据是否使用专门类型，还是先通过数组表达。
- 字典类型参数使用 `dict<string, int>` 还是其他分隔形式。

## 与当前实现的关系

当前编译器不支持：

- 数组字面量。
- 数组索引。
- 字典字面量。
- 字典读取或写入。
- 类型标注。
- 泛型或类型参数。

在这些能力真正进入实现前，应先新增对应版本设计文档和测试计划。

数组核心现已排入 v0.39，数组实用操作与遍历排入 v0.40。v0.39 设计时必须明确选择：

- 仅通过数组字面量推导元素类型；或
- 同时加入数组所需的最小变量类型标注。

这不等于通用变量类型标注或完整类型推导已经排入 v0.39。字典实现已经登记到待编号
开发池，具体版本要在数组、字符串与基础类型规则稳定后确认。
