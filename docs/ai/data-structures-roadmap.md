# 数据结构实现边界与后续规划

最后更新：2026-09-07

## 目的

本文记录 LAI / 灵语已实现的局部数组核心及后续数据结构命名方向，区分当前事实、已编号规划和未编号候选。

当前 v0.40 第一阶段在局部 `int[]`、`string[]`、`bool[]` 的显式创建和索引读取上新增元素修改；长度 API、遍历、多维、动态列表和字典仍未实现。

v0.40 仍待实现只读长度和遍历，不代表全量完成；v0.41 多维数组不顺延，其后依次为反向循环、字符串/最小用户标准库、浮点数、LLVM 变量模型与语义复盘。v0.40-v0.45 仍有 6 个尚有工作的编号版本；数组参数/返回、整数组复制/赋值、动态 `list<T>` 和字典均属于未编号候选。

## 命名原则

- 优先照顾 C# 程序员的阅读习惯。
- 保持语法短小，不引入过重的泛型外观。
- 避免同一个词在类型名和常用操作中产生不必要混淆。
- 新增数据结构前必须先写设计、计划和测试。

## 已确认的命名方向

### 数组：`int[]`

当前局部数组采用已确认的 C# 风格后缀写法：

```lai
let scores: int[] = [90, 95, 100]
```

原因：

- 对 C# 程序员更直观。
- `int[]` 一眼能看出“元素是 `int` 的数组”。
- 远期文档中曾出现过 `[]int` 示例，但该示例不作为正式决定。

已确认的语义方向：

- `int[]` 是固定长度数组：创建后长度不变，不支持 `append`、`remove` 或自动扩容。
- v0.40 第一阶段已实现元素修改：三种元素允许同型 `=`，仅 `int` 元素支持 `+= -= *= /= %=`。
- 固定长度不等于完全不可变；v0.40 的元素更新只替换已有位置，不改变数组长度。
- 动态长度容器不复用数组语义，未来独立设计为 `list<T>`。

v0.39 已实现必需显式数组声明，并支持当前三种基础元素类型：

```lai
let scores: int[] = [90, 95, 100]
let names: string[] = ["LAI", "LingYu"]
let flags: bool[] = [true, false]
let empty: int[] = []
```

数组字面量中的所有元素必须与声明类型一致，不允许混合元素类型。`int[][]` 等多维数组不属于 v0.39，已单独插入 v0.41；矩形数组、交错数组和最终类型形式留到该版本设计时确认。

数组字面量只用于显式声明的直接初始化值，元素从左到右各求值一次。读取为 `scores[index]`，索引严格为从 0 开始的 `int`，合法范围 `0 <= index < length`。静态可算出的越界为编译错误，动态越界在访问前输出含行号、index、length 的运行时错误并 `EXIT_FAILURE`。索引结果可复用既有标量表达式、打印、函数实参和返回，但数组整体不能跨函数传递或复制。

元素修改先求值索引并检查边界，再读取旧值（复合赋值），再求值右值，各阶段单次执行，成功才写入。索引失败不执行右值，右值或 checked i32 算术失败不写入；静态零除和边界规则保留。修改是语句，目标仍限局部数组名及括号形式。

局部 C 存储随块生命周期结束，空数组物理占位 1、逻辑长度 0；本版不用 VLA、堆分配或 GC。`examples/local_arrays.ly` 实际输出 `95`、`LAI`、`1`，`bool` 沿用数字打印。LLVM 范围未扩大，数组声明仍会被后端以 `LetStmt` 能力错误拒绝。

### 字典：`dict`

未来键值表优先命名为 `dict`：

```lai
let ages: dict<string, int> = {
    "Alice": 18
}
```

原因：

- `dict` 对有 C# / Python 背景的读者都比较容易理解。
- 避免类型名 `map` 和集合操作 `.map(...)` 撞名。
- 比 `Dictionary` 更短，更符合 LAI 极简语法方向。

暂定示例：

```lai
dict<string, int>      // 字符串到整数
dict<string, bool>     // 字符串到布尔值
dict<int, string>      // 整数到字符串
```

## 尚未确认的方向

以下数据结构还没有完整设计：

- 动态列表已确定不复用数组，类型方向为 `list<T>`；其 API、内存语义和版本号仍未确认。
- 集合是否命名为 `set`。
- 结构化数据使用 `struct`、`record` 还是其他关键字。
- 张量和批量数据是否使用专门类型，还是先通过数组表达。
- 字典类型参数使用 `dict<string, int>` 还是其他分隔形式。

## 与当前实现的关系

当前编译器不支持：

- 隐式数组类型、长度 API、数组遍历、方法、切片或多维数组。
- 数组参数/返回、整数组复制/赋值/比较/打印。
- 字典字面量。
- 字典读取或写入。
- 通用标量变量类型标注；局部显式类型标注目前仅覆盖三种一维数组。
- 泛型或类型参数。

在这些能力真正进入实现前，应先新增对应版本设计文档和测试计划。

数组核心已在 v0.39 实现，数组实用操作与遍历排入 v0.40，多维数组插入 v0.41。局部声明必须显式写出 `int[]`、`string[]` 或 `bool[]`；该能力只覆盖数组所需的最小变量类型标注，不代表通用变量类型标注已经实现。

版本任务边界已经确认：

- v0.39（已实现）：显式类型的固定长度局部数组创建、只读索引、元素类型检查、索引类型/边界检查和局部 C 表示。
- v0.40：第一阶段元素索引更新已实现；只读长度和最小遍历仍待实现，不加入改变长度的操作。
- v0.41：多维数组最小闭环；类型形式、矩形/交错语义和内存模型必须先单独设计确认。
- 待编号开发池：独立动态 `list<T>`，后续再设计扩容、`append`、`remove` 和遍历。
- 待编号开发池：数组参数和数组返回，先确定生命周期、所有权与跨函数传递规则；当前未实现且没有确定版本。
- 待编号开发池：整数组复制与整体赋值，先确定值复制、别名、长度兼容和存储规则；当前未实现且没有确定版本，不默认并入 v0.40 或 v0.41。

这不等于通用变量类型标注或完整类型推导已经排入 v0.39。字典实现已经登记到待编号
开发池，具体版本要在数组、字符串与基础类型规则稳定后确认。
